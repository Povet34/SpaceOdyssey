# 이어서 하기

작성일 2026-11-24. 다른 컴퓨터나 새 세션에서 이 프로젝트를 이어 갈 때 가장 먼저 읽는 문서다.

## 1. 프로젝트 한 줄

인류 한 명이 우주선 한 척을 타고 동면을 반복하며 우주의 종말을 보러 가는 1인 생존 게임이다. 캐치프레이즈는 "죽기 위해 생존한다". Unity 6(URP) 프로젝트이고 저장소 루트 아래 `SO` 폴더가 Unity 프로젝트다.

지금은 기획 단계다. 게임 본편 코드는 없고, 우주선 블록아웃 프로토타입과 퀘스트 자료 도구만 있다.

## 3. 지금 있는 것

**기획**
- 컨셉 문서가 한 사이클, 무드와 몸, 동면과 이동, 시간과 시대, 테크, 이벤트, 교역, 선박 패널, 우주선, 엔딩까지 다룬다.

**퀘스트**
- 새 형식(낱장 사건, JSON)으로 옮긴 예시 사건 29장, 줄기 8개가 `SO/Content/base/`에 있다.
- 검사 도구와 지도 도구가 `SO/Tools/QuestMap/`에 있다. `퀘스트지도열기.bat`을 두 번 누르면 브라우저에 지도가 뜨고, `퀘스트검사.bat`은 검사만 돌린다. Python 3이 필요하다.
- 씨앗은 1차 묶음 여덟 개에 269개가 있다. 풀 때 쓰는 테크와 물건을 모은 수단 목록도 `SO/Docs/QuestSeeds/00_Means.md`에 있다. 표본 리뷰의 판정이 "고쳐야 함"이라 고르기 전에 손봐야 한다.

**우주선**
- 블록아웃 씬이 `SO/Assets/Scenes/`에 있다 (`ShipBlockout`, `ShipBlockout_Large`).
- 스크립트는 `SO/Assets/Scripts/ShipBlockout/`, 프리팹은 `SO/Assets/Prefabs/`에 있다.
- Tab으로 뚜껑을 여닫아 내부와 외부를 바꿔 보고, WASD로 이동한다. 칸의 변에 벽과 문을 놓는 프로토타입이 있다.

## 4. 이어서 할 일

### 기획 (이 문서를 쓴 세션이 맡던 일)

1. **퀘스트라인 100개 고르기.** 사용자가 마음에 드는 번호와 별로인 번호를 아직 고르지 않았다. 고른 결을 따라 늘리거나 고친다.
2. **테크 예시 고르기.** 47개 가운데 느낌이 맞는 것과 아닌 것을 사용자가 아직 고르지 않았다.
3. **컨셉 문서 16장의 제안 여덟 개.** 확정으로 올릴지 뺄지 사용자 답이 없다.
4. **컨셉 문서 17장의 미정 열 가지.** 특히 시간 구간별로 무엇이 나오는지, 시작 세팅, 죽었을 때 다음 판에 남는 것, 교역의 화폐와 상대.
5. **퀘스트라인 예시와 테크 꼬리표 잇기.** 100개는 아직 테크 꼬리표와 연결되지 않았다.
6. **《목성의 노래》를 옮긴 097번 "공명".** 오마주로 둘지 뺄지 사용자 답이 없다.

### 퀘스트 체계

[QuestSeeds/README.md](QuestSeeds/README.md)의 "이어서 할 일"과 [QuestSystemDesign.md](QuestSystemDesign.md)를 본다. 큰 줄기는 이렇다.

1. 모은 씨앗 여덟 묶음을 리뷰대로 손본다. 고칠 것은 [QuestSeeds/REVIEW_2026-11-24.md](QuestSeeds/REVIEW_2026-11-24.md)에 있다.
2. 연출자(무엇을 언제 낼지 고르는 부분)는 설계만 있다. 구현하지 않았다.
3. 게임이 `Content` 폴더의 파일을 읽는 코드가 없다.
4. 지도 도구가 좁은 창에서 처음에 지도를 왼쪽 위에 아주 작게 그렸다. 보통 크기의 브라우저에서 같은지 확인하지 않았다.
5. `Quests/`의 100개 가운데 새 형식으로 옮긴 것은 일부다.

### 우주선

[ShipBuildDesign.md](ShipBuildDesign.md) 끝의 "이어서 할 일"을 본다. 그 문서 12장에 사용자가 정해야 할 질문이 있다.

## 5. 작업 규칙

사용자와 일하면서 정해진 것이다.

- 한국어로 대화하고 반말 톤을 쓴다.
- 작업 단위가 끝날 때마다 묻지 않고 main에 바로 커밋한다. 브랜치는 만들지 않는다. 푸시는 사용자가 말할 때만 한다.
- 사용자는 느낌을 잡는 대화를 반복하면서 기획을 풀어 간다. 한 번에 확정하려 들지 않는다.
- 사용자는 SF에 익숙하지 않다. 예시를 달라고 하면 충분히 많이 만들고, 용어는 풀어서 설명한다.
- 컨셉 문서의 "제안"은 확정된 것처럼 다루지 않는다.
- 제안하지 않는 것: 전투 중심, 여러 명의 승무원, 처음부터 보이는 테크트리, 수명 제한, 플레이어가 직접 채굴하는 방식, 선택지 창 위주의 이벤트, 시대를 챕터로 나누는 구조.

## 6. 다른 컴퓨터에서 시작하는 법

1. 저장소를 받는다.
2. Unity Hub에서 `SO` 폴더를 연다. Unity 6000.6.10f1이다.
3. Unity MCP를 쓴다면 에디터의 `Window > MCP for Unity`에서 연결을 켠다.
4. 새 세션에 이 문서와 [GameConcept.md](GameConcept.md)를 먼저 읽게 한다.

이전 컴퓨터에 있던 대화 기록과 세션 메모리는 저장소에 들어 있지 않다. 필요한 내용은 이 문서와 위 문서들에 옮겨 적었다.
