# 블록 격자 모델 계획서 (통로 그물 계획의 후속)

상태: **승인됨**(2026-11-25, N0 통과. critic 비평 반영). 작성 2026-11-25. 승인 시점까지 코드, 씬, 프리팹은 바꾸지 않았음. 다음은 N1 구현(6장).

이 문서는 `ShipLayoutNetworkPlan.md`(이하 "옛 계획서")의 **블록 크기와 통로 모델을 대체**함. 용어, 모듈은 별개 층, 걸음을 막는 모듈, 완전 단절 배치 거부, 분리 규칙, 에셋 규칙은 옛 계획서에서 이어받음(5장 대응표). 수치는 전부 **출발값**이고 화면을 보고 고칠 값임. 수치보다 "그 값이 무엇을 뜻하는가"를 먼저 읽으면 됨. 각 장은 따로 읽어도 되게 씀.

## 0. 한눈에

### 0.1 문제 (사용자 판정, 2026-11-25)

A1 화면(블록 5개가 이어 붙은 배)을 본 사용자의 판정: **"블록이 너무 크다. 저걸 하나씩 떼어낼 수 없다."** 사용자가 의도한 블록은 **3×5칸 조각 하나**이고, 그중 **2×2칸만 가압구역, 나머지는 설비구역**임. 이런 조각을 격자에 맞춰 이어 붙이며 배를 덩어리로 만듦.

원인은 외피가 아니라 **스케일 오해**임. 옛 계획서는 "배 한 척을 블록 4~5덩이로 나눈다"(옛 11.2절)로 잡았고, Backpack Battles의 "가방"을 큰 선체 덩어리로 읽었음. 그 게임의 가방은 작은 조각 여러 개임. 블록 하나가 통로 여러 개와 방 여러 개를 품고 있어서 하나만 떼어낼 수도 없었음. 옛 계획서의 critic 비평 두 번도 이것을 못 잡았고, 화면 판정이 잡았음.

### 0.2 새 모델 한 줄

**배 = 같은 크기(3×5칸) 블록 조각을 격자에 맞춰 이어 붙인 것.** 블록마다 가압 2×2(자리는 블록 종류마다 다름)와 설비 11칸이 있고, 블록은 90도씩 돌려 붙일 수 있음. **통로와 방은 이웃한 블록의 가압 2×2가 변을 맞대며 이어지면서 생김.** 블록 하나가 분리와 재배치의 단위임. **블록을 붙이는 것은 자유(칸이 겹치지만 않으면 됨)이고, 가압구역을 서로 이어 붙이는 것은 플레이어의 몫임.** 이어지지 않은 가압구역에 모듈을 설치하면 오류가 남(3장).

배 전체 칸 지도, 방, 외피, 놓을 수 있는 칸은 위에서 결정론적으로 다시 만듦(저장 안 함). 블록은 겹칠 수 없음.

### 2.3 프리셋 텍스트 (A1 후속 단계에서)

옛 2.6절 문법을 이어 씀: `block <식별자> <종류이름> <x> <z> <회전>`, `start <x> <z>`, 모듈 줄은 모듈 단계에서. 식별자는 공백과 `+`가 없는 문자열. 회전은 0, 90, 180, 270 중 하나이고 그 밖의 값은 예외. 오류는 파일 줄 번호와 함께 예외.

### 2.4 회전과 좌표 (critic 비평 반영)

- 좌표는 위에서 내려다본 모습에서 +x가 오른쪽, +z가 위쪽임. 블록 종류의 칸 지도는 **회전 전 3열×5행**이고 칸은 (u, v)로 부름(u는 0~2 열, v는 0~4 행, v=0이 아래).
- **90도 시계 방향 회전**: 칸 (u, v)는 (v, w−1−u)로 가고(w는 회전 전 너비), 회전 뒤 크기는 높이×너비가 됨. 3×5는 5×3이 됨. 180도와 270도는 이것을 두 번, 세 번 적용한 것임.
- 배치 줄의 (x, z)는 **회전한 경계 상자(3×5 또는 5×3)의 왼쪽 아래 칸이 놓일 배 좌표**임. 상자가 음수 쪽으로 뻗지 않음.
- 설비 칸 손상 기록은 블록 자기 좌표(회전 전 3×5 지도 기준)로 저장하고, 배 좌표로 바꿀 때 같은 회전 변환을 씀.
- 뒤집기(거울) 조작은 없음. 거울상은 별개 종류로 카탈로그에 둠.

### 2.5 블록 종류 파일 형식 (critic 비평 반영)

- 파일 하나가 종류 하나. 종류 이름은 파일 이름(확장자 제외). 5줄이고 한 줄이 3글자이며 **첫 줄이 위쪽(+z 쪽)**. 줄 첫 글자가 `;`인 줄과 빈 줄은 건너뜀(프리셋과 같음).
- 글자: `o` 가압 칸, `#` 설비 채움, `%` 설비 장갑, `~` 설비 탱크, `^` 설비 엔진. 그 밖의 글자(`.` 포함)는 "알 수 없는 글자" 예외.
- 검사(전부 줄 번호와 글자 위치를 담은 예외): 5줄이 아님, 한 줄이 3글자가 아님, `o`가 정확히 **2×2 직사각형 하나**가 아님.
- 옛 `Blk_*.txt` 4장(큰 형판)은 N1 시작 때 지우고, 같은 접두 `Blk_`로 새 종류 파일을 만듦(비교 기준은 커밋 `c484d07`, `eff5b98`).

## 3. 규칙

### 3.1 가압 연결과 도달

두 가압 칸이 변을 공유하고 그 변이 벽이 아니면 이어짐. 같은 블록의 가압 2×2는 항상 한 덩어리. 블록 사이는 접합 변이 열려 있어야 이어짐(차단막은 열린 변으로 넘김. 진공 규칙은 나중). **도달 가능** = 시작 칸에서 이어진 가압 칸을 따라 모든 가압 칸에 닿음. 시작 칸에서 도달할 수 없는 가압 칸 덩어리를 **고립 가압구역**이라 부름. 고립 가압구역은 블록 붙이기에서는 허용하고(3.2절), 모듈 설치에서는 막음(3.4절).

### 3.2 블록 붙이기 규칙 (싼 것부터)

**블록 붙이기는 자유임**(사용자 보충, 2026-11-25: "테트리스처럼 맘대로 붙일 수 있음"). 연결을 강제하지 않음.

1. 칸 격자에 정렬(정수 좌표, 회전 4가지).
2. 다른 블록과 칸이 겹치지 않음.
3. 맞닿음. 프리셋을 읽을 때는 **배 전체가 칸의 변 맞닿음(모서리 대각선은 아님)으로 한 덩어리**여야 함(줄 순서와 무관). 대화형 붙이기(N2)에서는 **새 블록의 칸 하나 이상이 기존 블록의 칸과 변을 공유**해야 함. 허공에 뜬 블록을 막으려는 AI 추천이고 8.4절에서 사용자에게 확인함.

이 세 가지를 어기면 거부함. **가압구역이 이어지는지는 거부 사유가 아니라 표시임**: 붙인 뒤 **배 전체의 가압 칸을 시작 칸에서 다시 훑어**, 닿지 않는 가압구역을 **고립 가압구역**으로 표시함(색, 콘솔. 새 블록이 옛 고립 구역을 이을 수 있으므로 새 블록만 보지 않음). 가압 2×2가 어긋나게 닿으면 폭 1칸 통로, 나란히 닿으면 폭 2칸 통로가 생기고, 설비 칸끼리만 닿으면 이어지지 않음. **가압구역을 서로 이어 붙이는 것이 플레이어의 퍼즐**이고, 못 이으면 거기에 모듈을 못 놓는 대가를 치름(3.4절).

### 3.3 블록 떼기(분리) 규칙

떼려는 블록을 B라 하면 다음을 모두 만족해야 함: (1) **B에 걸친 모듈이 없음**(걸친 모듈은 먼저 치움. 옛 7.4절). (2) **B 위의 모듈은 보관함으로** 가고(보관함이 생길 때까지 분리 적용을 미룸), **나머지 설치 모듈은 떼고 난 뒤에도 접근 칸 하나 이상이 시작 칸에서 도달 가능**함(어느 모듈이 끊기는지 이유와 함께 거부. **모듈이 없는 가압구역이 고립되는 것은 허용**). (3) 남은 배에 **엔진 설비**가 하나 이상(엔진 역할 `^` 칸이 있는 블록 하나 이상. 배기 방향 규칙은 N2 앞에서 따로 정함). (4) 시작 칸이 남은 쪽에 있음. (5) **남은 블록들이 칸의 변 맞닿음으로 한 덩어리**(3.2절 규칙 3과 같은 기준. 규칙 3을 빼면 이 조건도 같이 뺌). 떼어 낸 블록은 버림으로 시작하고 손상 기록을 통째로 들고 나감(옛 12.2절 결정 그대로).

### 3.4 모듈 놓기 규칙

옛 4.3절을 이어받되 방칸을 가압 칸으로 읽음. 달라지는 것: **문 안쪽 비움(옛 규칙 4)과 벽 가로지름(옛 규칙 3)은 없어짐**(문과 벽이 없는 모델이라서. 차단막이 있는 접합 변을 모듈이 가로지를 수 있는지는 8.1절). 남는 것: 점유 칸이 전부 가압 칸, 다른 모듈과 안 겹침. **새로 생긴 것: 점유 칸이 시작 칸에서 도달 가능해야 함. 고립 가압구역에 설치하려 하면 오류**("이 가압구역이 시작 칸과 이어지지 않음", 사용자 보충 2026-11-25). 그리고 놓은 뒤에도 시작 칸에서 도달 가능하던 빈 가압 칸과 모든 모듈의 접근 칸이 계속 도달 가능함(모듈이 길을 끊지 않음. 옛 규칙 5와 6을 합침). 모듈은 점유 칸 전체가 걸음을 막음. 모듈 크기 규격은 가압 2×2에 맞춰 1×1, 1×2, 2×2가 기본이고, 더 큰 모듈(2×3 등)은 **이웃한 두 블록의 가압 칸에 걸쳐서만** 놓임. 걸침이 자연스러운 이유임.

**시작 칸은 모듈의 점유 칸이 될 수 없음**(도달 검사의 출발점이 사라지므로). **오류의 두 종류**(critic 비평 반영): 프리셋을 읽을 때 모듈이 고립 가압구역에 있으면 **예외**(데이터가 깨진 것. 모듈이 없는 고립 가압구역은 정상이고 콘솔에 개수만 찍음). 대화형 설치(개발 키, 나중의 패널)에서는 **이유 문자열을 돌려주고 거부**하며 배는 그대로임.

### 3.5 사건 엔진 연동 (본부)

"모듈 이름 → 칸 좌표" 조회는 그대로 가능함. 달라지는 것은 "문 칸"이 없어지고 **접근 칸**이 그 자리를 대신하는 것. 질의 형식은 구현 전에 본부와 맞춤. **불변식: 설치된 모든 모듈의 접근 칸은 시작 칸에서 도달 가능한 덩어리에 속함.** 3.4절(설치 검사), 3.3절(분리 조건 2), 프리셋 읽기(예외)가 이것을 지킴. 따라서 이름 조회가 닿지 않는 장소를 돌려주면 불변식 위반이므로 **예외로 드러냄**(조용히 건너뛰지 않음).

## 4. 크기와 규격

### 4.1 칸 크기 (노브)

- **칸 한 변의 길이: 출발 2m.** 가압 2×2 = 4m×4m 방 하나, 블록 = 6m×10m, 폭 2칸 통로 = 4m. 칸이 1m일 때는 방 하나가 2m×2m로 너무 작았음.
- 방 높이 3m, 층 높이 4m, 캐릭터 폭 0.6m는 미터 값이라 그대로. 칸을 키우면 높이 대비 칸이 넓어져 천장이 낮게 느껴질 수 있음(화면 판정).
- **칸을 키우면 같은 걷는 속도에서 방 사이 이동 시간이 길어짐.** 본부의 프로토타입과 사건 엔진이 이동 시간을 쓰므로 값이 정해지면 본부에 알림.
- **칸 1m가 코드에 박혀 있음**(코드를 열어 확인함, 2026-11-25): 미리보기가 위치와 크기에 `+0.5f`, `1f`를 직접 쓰고, `EdgeKey.Center`(접합 선과 차단막 띠의 위치)가 칸 1m 기준이고, 컨트롤러와 변 편집기가 월드 좌표를 `FloorToInt`로 칸으로 거꾸로 읽음. **그래서 부모 Transform 크기만 키우면 칸 좌표가 깨짐.** N1에서 칸 크기를 미리보기의 직렬화 필드 하나로 두고 미리보기가 모든 위치와 크기에 곱함. 컨트롤러와 변 편집기의 칸 역산은 이 값으로 나누도록 고치거나, 네트워크 씬에서 벽 그룹이 비어 있어 영향이 없는지 먼저 확인함(**미확인**).

### 4.2 가압 비율

블록당 가압 4칸 / 15칸 = 약 27%. A0, A1의 낮은 가압 비율(약 27%)과 같은 선이라 "기계 속에 파인 길" 느낌은 유지됨(호텔로 되돌아갈 위험이 낮은 쪽).

## 6. 단계

각 단계는 독립적으로 멈출 수 있고, 단계마다 **사용자가 화면에서 한 단어로 판정**함. 모든 단계에서 별도 컨텍스트 리뷰어가 코드를 봄. 한 단계 한 커밋. 작업 씬은 `ShipBlockout_Network`.

| 단계 | 하는 것 | 사용자가 판정할 것 |
|---|---|---|
| **N0** | 이 계획서 승인 | **완료(2026-11-25)**: 8장 질문 답과 승인 |
| **N1. 블록 격자 판**(구현과 독립 리뷰 완료, 판정 "잘 읽힘") | 블록 종류 카탈로그(출발 6종, 8.3절)와 프리셋(블록 12~16개로 배 하나, 회전 포함)과 고립 가압구역이 하나 있는 확인용 프리셋을 읽어 격자 위에 블록을 깔고, 블록마다 색, 가압 2×2 판, 설비 판, 접합 선을 그림. 규칙은 붙이기 규칙 1~3(정렬, 겹침, 맞닿음)이고 **연결은 강제하지 않고 표시함**(시작 칸에서 이어지지 않은 가압구역을 고립으로 색 표시, 콘솔에 개수). 칸 크기 노브. 걸을 수 있음. 모듈, 차단막 띠(8.1절 결정에 따라), 외피, 데이터 에셋, 테스트는 없음 | "조각을 이어 붙인 배로 읽히는가", "가압 2×2끼리 이어진 통로를 걸을 만한가(폭, 답답함, 칸 크기)" |
| **N2. 붙이기와 떼기 시험** | 패널 전 개발용 키로 블록 하나를 붙이는 위치를 보임(**초록 = 붙고 가압구역이 이어짐, 노랑 = 붙지만 고립 가압구역이 생김, 빨강 = 겹침이나 안 맞닿음으로 거부**)과 떼기 가능 판정(3.3절, 거부 이유)을 보임. 퍼즐이 되는지 확인 | "붙이고 떼는 맛이 있는가, 거부 이유가 읽히는가" |
| **N3. 모듈 회색 상자** | 옛 A2의 일반화(3.4절). 걸친 모듈 하나 포함. **고립 가압구역에 설치하면 오류**가 나는 것을 일부러 고립시킨 프리셋으로 확인 | "블록과 모듈이 따로 읽히는가", "막힌 모양이 걸을 만한가" |
| N4 이후 | 데이터 형식 2와 테스트, 생성기(벽, 차단막, 충돌체, 조명), 외피, 내부 뷰, 개조, 방 용도 표시 | N3 판정 뒤 블록 모델 기준으로 다시 쪼개서 계획 |

**N1 수용 기준**(critic 비평 반영):
- 콘솔에 블록 수, 접합부 수, 접합 변 수(가압↔가압은 따로), 고립 가압구역 수가 찍힘.
- 깨뜨린 확인용 프리셋(`Assets/Prefabs/Ship/Network/Broken/`)이 각각 줄 번호가 담긴 예외로 멈춤: 칸 겹침, 배가 한 덩어리가 아님(맞닿지 않음), 3×5가 아닌 종류, 가압이 2×2가 아닌 종류, 90의 배수가 아닌 회전값, 시작 칸이 설비 칸, 알 수 없는 종류 이름.
- 고립 가압구역이 있는 정상 프리셋은 예외 없이 열리고 고립만 표시됨.
- Play 후 콘솔 오류와 경고 0(일부러 깨뜨린 데이터로 확인하는 예외는 제외).
- 걸어서: 설비 칸에 못 들어감, 접합부를 지나 이어진 가압구역으로 걸어감.
- **코드는 `ShipNetworkRules`를 제자리에서 고치고 새 클래스를 만들지 않음.** 옛 `Blk_*.txt` 4장, `Ship01_A1.txt`, `Broken/`의 옛 파일은 N1 시작 때 지움(비교 기준은 커밋 `c484d07`, `eff5b98`).

N1이 이 계획의 핵심 검증임. 사용자 규칙대로 **기본값은 안전하고 밍밍한 쪽으로 치우치므로**, N1의 프리셋은 일부러 극단까지 밀어서 그림(회전을 섞고, 폭 1칸 어긋남과 폭 2칸 나란함을 둘 다 만들고, 잎 방이 있게).

| 위험 | 내용 | 대응 |
|---|---|---|
| 같은 조각의 단조로움 | 3×5 조각 하나를 반복하면 가방 놀이처럼 보이고 배가 안 읽힐 수 있음 | 가압 자리 다른 종류, 거울상 종류, 회전, 설비 역할 색. N1 판정 |

| 접합부 수 폭증 | 블록이 작아져 접합부와 접합 변 수가 많아짐. 8.1절 차단막 결정이 이 수를 좌우 | N1 콘솔에 접합부 수와 접합 변 수 출력 |
| 쓸모없는 고립 방 | 붙이기가 자유라 이어지지 않는 가압구역(쓸모없는 방)이 생김 | 표시(색, 콘솔)로 알리고 모듈 설치만 막음. 사용자가 "고립을 아예 못 만들게" 원하면 3.2절에 도달 규칙을 되살림(한 줄) |
| 연결 오류가 늦게 드러남 | 연결 검사가 모듈을 놓을 때만 있으면 플레이어가 고립 방을 뒤늦게 앎 | 붙이기 단계에서도 초록, 노랑 표시로 미리 보여 줌(N2) |
| 칸 크기 상수 | 코드의 칸 1m 상수와 카메라, 충돌체, 걷는 속도 | 4.1절에 확인한 사실대로 N1에서 필드로 바꿈 |

## 8. 열린 질문과 추천

### 8.1 블록 사이의 가압 연결에 차단막을 항상 둘까

**결정(2026-11-25, 사용자): B 열린 변.**

- **무엇이 걸렸나**: 옛 결정은 "접합부를 지나는 통로 변은 항상 차단막(종류 고정)"이었음. 그 결정은 블록이 클 때 "통로 한 줄이 접합부를 지남"을 전제로 했음. 블록이 3×5로 작아지면 **블록이 맞닿는 곳마다 차단막**이 되어 통로가 몇 칸마다 문으로 끊김. 또 차단막이 있는 변을 모듈이 가로지를 수 없다고 하면 **걸친 모듈이 불가능해짐**(걸침 허용은 사용자 결정).
- **선택지**: A. 항상 차단막(옛 결정 유지. 블록 = 진공 구획 = 분리 단위로 깔끔하나 문이 매우 많고 걸침 불가). B. 접합 변은 기본 **열린 변**이고 차단막은 따로 둠(걸침 가능. 차단막은 N3 이후에 "구획 계산"과 함께 정함). C. 블록 종류가 가압 2×2의 가장자리에 **접속구 차단막 자리**를 가짐(블록 설계로 구획을 정함. 개념이 하나 늘어남).
- **추천: B.** 걸침을 살리고, N1을 "조각이 이어 붙은 배로 읽히는가"만 판정하게 단순하게 유지함. 차단막(진공 구획)은 진공 규칙(설계 13.4절)이 생길 때 A와 C 중에서 화면을 보고 다시 정함. 사용자가 "차단막이 있어야 구획이 보인다"고 하면 C를 N1에 넣음.

### 8.2 칸 크기 값

- 출발 2m(방 4m×4m, 블록 6m×10m, 폭 2칸 통로 4m). 사용자가 "키움"만 정했고 수치는 안 정했음. 화면에서 캐릭터 대비 비율을 보고 한 단어("좁다", "휑하다")로 정함. 노브이므로 N1에서 바꾸는 비용이 작음.

### 8.3 블록 종류를 몇 개로 시작할까

- 가압 2×2의 자리는 3열×5행 안에서 8가지이고 **회전으로 보면 4종류**임(끝 한 쌍, 치우침 한 쌍. 각 쌍은 서로 거울상이라 별개 종류로 둠). 정가운데 자리는 없음(코드와 계산으로 확인함). **추천: 6종으로 시작** = 가압 자리 4종(일반, 설비 채움) + 엔진 1종(끝) + 탱크 1종(치우침). 단조로우면 N1 판정 뒤 설비 역할 변형을 늘림. 수는 노브.

### 8.4 사용자가 정하지 않아도 되는 것(AI가 추천으로 정함)

**결정(2026-11-25, 사용자): 맞닿아야 함(규칙 3 유지).**

0.4절 표. 화면 판정에서 되돌림. 특히 붙이기 규칙 3(맞닿음)은 AI 추천임: 사용자 말("맘대로 붙일 수 있음")이 허공에 뜬 블록까지 허용하는 뜻이면 3번을 뺌(한 줄).
