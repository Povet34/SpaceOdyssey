# 퀘스트 씨앗 모음

작성 시작 2026-11-24. 스페이스 오페라, 하드 SF, 우주론, 신앙과 사이오닉을 다루는 작품과 자료에서 "이 게임에서 일어날 법한 일"을 모은 창고다. 완성된 퀘스트가 아니라 씨앗이다. 마음에 드는 것을 골라 [QuestSystemDesign.md](../QuestSystemDesign.md)의 사건 형식으로 옮긴다.

전제는 [GameConcept.md](../GameConcept.md)를 따른다. 혼자, 배 한 척, 동면을 되풀이하며 우주의 끝까지 간다. 사건은 선택지 창이 아니라 배 어딘가의 변화로 나타난다. 육체적 전투는 거의 없다.

## 모으는 기준

- 핍진성이 있으면 모은다. 실제 과학, 잘 짜인 설정, 오래 살아남은 이야기 틀이 근거다.
- "창이 깨진다" 같은 흔한 고장은 모으지 않는다. 그 시대에만, 그 상황에서만 일어나는 일을 모은다.
- 남의 작품에서는 **틀과 원리만** 가져온다. 고유 이름, 인물, 세력, 문장은 가져오지 않는다. 씨앗 안에서는 우리 말로 새 이름을 붙인다. 어디서 왔는지는 "뿌리" 칸에 작품 이름으로만 적는다.
- 혼자 있는 사람과 배 한 척에게 일어날 수 있는 모양으로 바꿔 적는다.
- **"한다, 안 한다"로 쓰지 않는다. "무엇으로 어떻게 푸나"로 쓴다.** 받는다와 거절한다, 둔다와 치운다, 연다와 안 연다 같은 양자택일은 푸는 길이 아니다. 안 하는 쪽은 "방치" 줄이 맡는다. 푸는 길은 수단이 서로 다른 방법들이고, 길마다 과정과 남는 것이 다르다.
- **풀려면 무엇이 있어야 하는지를 같이 적는다.** 수단의 이름은 [00_Means.md](00_Means.md)에서 고른다. 수단의 상태(탑재 중, 배양 중, 대체됨)와 물건의 내력(분해 안 함, 읽지 않음)으로 갈리는 길을 넣는다.
- 이야기가 끊기지 않게 쓴다. 왜 벌어졌는지, 어떤 장면인지, 풀고 나면 무엇이 달라지는지가 이어져야 한다.

## 씨앗 한 개의 모양

```
### 제목
시기: ... · 노리는 곳: 배 / 나 / 일손 / 앎 · 결: 과학 / 신앙 / 사이오닉 / 초월 / 만남 / 유물

사정: 3~5문장. 무슨 일이 왜 벌어졌고 어떤 장면인가. 읽으면 그림이 떠야 한다.

- 징후: 처음 눈에 띄는 것. 그리고 며칠 지켜보면 더 드러나는 것.
- 걸림돌: 왜 그냥은 안 풀리나. 무엇이 모자라나.
- 푸는 길: 4~6개. 수단이 필요한 길이 셋 이상이고 수단의 갈래가 서로 달라야 한다.
  - **[수단] 길의 이름** — 어떻게 하나를 2~4걸음으로 적는다. 도중에 무엇이 보이나. → 결과. 남는 것: 물건, 바뀐 상태, 부작용.
  - 상태나 내력으로 갈리는 길을 하나 이상 넣는다. 예: `[하이퍼 드라이브 엔진: 탑재 중]`, `[어릴 때의 장난감: 분해 안 함]`.
  - 두 수단을 같이 써야 열리는 길을 넣으면 좋다. 예: `[플라즈마 도관 + 초전도 축전 고리]`.
- 맨손: 수단이 하나도 없을 때 할 수 있는 버티기나 미루기. 온전한 해결이 아니다.
- 방치: 두고 자면 어떻게 되나. (나빠짐 / 잦아듦 / 좋아짐 / 섞임)
- 물체: 이 일에 필요한 물건, 또는 끝나고 남는 물건.
- 엮임: 어느 길로 풀었느냐에 따라 뒤에 무엇이 달라지나. 다른 어떤 일과 이어지나.
- 뿌리: 어떤 과학이나 작품의 어떤 틀에서 왔나.
```

길끼리는 좋은 길과 나쁜 길로 나뉘지 않는다. 치르는 값이 다른 길들이다. 한 길을 읽으면 "그렇게 푼 배"가 다른 길로 푼 배와 어떻게 다른지 보여야 한다.

묶음 파일의 끝에는 "새로 필요한 수단" 표를 둔다. [00_Means.md](00_Means.md)에 없어서 지어 쓴 수단을 적는다.

```
| 이름 | 갈래 | 무엇인가 | 시기 | 이걸로 풀리는 것 | 대가 | 상태나 내력으로 갈리는 것 |
```

## 물체 한 개의 모양

각 파일 끝에 "물체" 장을 둔다.

```
| 이름 | 무엇인가 | 배에 두면 | 위험 | 뿌리 |
```

## 씨앗을 추가하거나 고칠 때 (지도 갱신)

씨앗은 따로 노는 글이 아니라 서로 이어진 그래프다. [Tools/SeedMap/](../../Tools/SeedMap/seedmap.py)가 씨앗, 퀘스트라인 100개, 수단을 한 그림으로 그린다. 씨앗을 쓰거나 고칠 때마다 이 순서로 한다.

1. 씨앗을 쓴다. 위의 모양을 지킨다.
2. `Tools/SeedMap/씨앗검사.bat`을 누른다(또는 `python Tools/SeedMap/seedmap.py check --suggest`). 오류가 0인지 보고, 새 씨앗의 연결을 본다.
3. **엮임을 보강한다.** 새 씨앗은 다른 씨앗을 하나 이상 가리키고, 다른 씨앗이 하나 이상 이 씨앗을 가리켜야 한다. 검사 결과의 "엮임 보강 후보"(같은 드문 수단을 쓰는데 아직 안 이어진 씨앗)를 참고한다. 가리키는 쪽 씨앗의 "엮임" 줄에 **따옴표로 제목**을 적는다. 어느 길로 풀었느냐에 따라 상대 씨앗이 어떻게 달라지는지 한 문장으로 적는다.
4. `Tools/SeedMap/씨앗지도열기.bat`을 눌러 지도를 다시 만들고 새 씨앗이 어디에 붙었는지 본다.
5. 커밋한다. 지도 파일(`seedmap.html`)은 언제든 다시 만들 수 있어서 커밋하지 않는다.

지도가 선을 긋는 기준:

| 선 | 어디서 읽나 |
|---|---|
| 씨앗 → 씨앗 (청록 화살표) | 엮임 줄에 따옴표로 적힌 다른 씨앗의 제목 |
| 씨앗 → 퀘스트라인 (회색 점선) | 엮임 줄에 따옴표로 적힌 퀘스트라인 제목, 또는 글 안의 `(078)` 꼴 번호 |
| 씨앗 — 수단 | 푸는 길의 `[수단: 상태]`. 선의 색이 상태다(탑재 중, 배양 중, 연구, 대체됨, 낡음, 내력) |

`[A + B: 탑재 중]`처럼 수단이 둘이면 상태는 바로 앞 수단(B)에만 붙는다. A도 그 상태라면 `[A: 탑재 중 + B: 탑재 중]`으로 적는다. 길이나 필드는 한 줄로 쓴다(이어지는 줄은 지도가 읽지 않는다).

씨앗 제목을 바꾸면 그 제목을 따옴표로 가리키던 엮임 줄도 고친다. 안 고치면 선이 끊기고 검사에서 "참고"로 뜬다. 씨앗을 새로 쓰는 일은 에이전트에게 맡겨도 되지만, 위 2~4번은 맡긴 쪽이 꼭 확인한다.
