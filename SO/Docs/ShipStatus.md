# 우주선 작업 인수 문서

작성 2026-11-24. 우주선(선체, 통로, 모듈) 작업을 다른 세션이 이어받을 때 **가장 먼저 읽는 문서**임. 이 문서는 "지금 어디까지 왔고 무엇이 정해졌고 다음에 무엇을 하는가"만 적음. 자세한 규칙과 이유는 계획서에 있고 여기서는 가리키기만 함.

전체 프로젝트 인수 문서는 [Handoff.md](Handoff.md)임. 이 문서는 그 우주선 절의 상세판임.

---

## 1. 한 줄 상태

통로 그물 + 블록/모듈 분리 모델의 **계획서가 3차 개정까지 끝났고(구현 전. 사용자 승인은 받았고 critic 비평도 반영함)**, 구현은 **A1(블록 판)까지 끝났고 독립 리뷰를 통과함**(2026-11-25). **A1 화면 판정이 나왔음(2026-11-25): 블록이 너무 크다, 방향 수정.** 블록을 3×5칸 조각(가압 2×2 + 설비 11칸)으로 바꾸고 격자에 테트리스처럼 이어 붙이는 새 계획서 `ShipBlockGridPlan.md`가 초안이고 **사용자가 승인함**(N0 통과, 2026-11-25). **N1(블록 격자 판)은 구현과 독립 리뷰를 통과했고 사용자 화면 판정은 "잘 읽힘"임**(2026-11-25). 다음은 N2(붙이기와 떼기 시험)인데 착수 전에 N2 상세를 정해야 하고(10절 7번), 주간 사용 한도가 거의 찼을 때라 시점은 사용자가 정함. A0와 A1은 각각 커밋했음(8절).

## 2. 결정된 것 (사용자 확정, 2026-11-24)

충돌하면 `ShipBuildDesign.md` 0.x절과 `ShipLayoutNetworkPlan.md`가 옛 본문보다 우선함.

| 항목 | 결정 |
|---|---|
| 칸과 높이 | 칸 1m, 방 안 높이 3m, 층 높이 4m. PC 전용, 그림체는 깎은 중간 폴리곤 |
| 통로 폭 | **간선 2칸, 지선 1칸.** `ShipBuildDesign.md` 0.1절의 "복도 1칸"을 사용자가 의식적으로 바꿈. 간선 폭은 걸어 보고 조정할 노브 |
| 작은 방 | 2×2, 2×3 허용(에어락, 창고 같은 작은 모듈). 기능 방은 3×3~4×4 유지 |
| 용어 | **블록**(선체 블록. 선체 덩어리, 백팩 배틀즈의 가방. 2026-11-25에 "세그먼트"에서 개명. 배 전체는 "선체") / **가압구역**(걷는 영역: 통로 칸 + 방칸) / **설비구역**(못 걷는 내부 영역, 배관·기계·탱크) |
| 구조 | 블록이 먼저 있고 모듈은 그 위의 **별개 목록**. 초기 우주선 = 블록 배치 + 모듈 배치의 프리셋 |
| 모듈 놓는 칸 | **가압구역의 빈 방칸에만.** 엔진, 탱크는 모듈이 아니라 설비구역에 고정된 블록 부품 |
| 경계 걸침 | **모듈은 블록 경계를 걸칠 수 있음.** 걸친 모듈이 있는 접합부는 모듈을 먼저 치워야 분리 가능(계획서 7.4절) |
| 모듈은 걸음을 막음 | **모듈이 차지한 N×M 칸 전체가 걸음을 막음**(충돌체가 점유 칸 전체를 덮음). 막힌 곳은 돌아가는 것이 정상이고, **동면 전에 배치를 잘 생각하는 것이 플레이의 일부**임. 배치가 방 사이 이동 시간을 바꾸고 그것이 사건에 대응하는 시간에 영향을 줌(본부의 사건 엔진과 프로토타입이 이동 시간을 씀). A2의 사용자 판정은 "막혀도 되는가"가 아니라 "막힌 모양이 걸을 만한가"(취향). 계획서 12.2절 |
| 완전히 끊기는 배치는 놓을 때 막음 | 배치, 편집, 개조 시점에 "여기엔 못 놓음"으로 거부함(놓기 규칙 6: 배의 모든 빈 방칸과 모든 모듈의 접근 칸이 통로 그물에서 닿아야 함). 차단막 닫힘, 불, 진공, 파손 같은 게임 중 상태 변화로 생기는 일시 단절은 허용. 이유: 본부 사건 엔진이 모듈 이름으로 장소를 조회해 걸어가므로 "못 가는 장소" 분기를 안 가져도 되게 함. 계획서 12.2절 |
| 차단막 | 통로 중간과 접합부에 차단막(도어락)을 둠. 접합부는 분리 지점. 접합 통로 변은 차단막 고정 |
| 설비구역 | 드론이 방문하지 않음. 내구도 값만 가짐. 수리는 선체 전체 보강이라는 추상 표현 |
| 확장 | 블록 붙이기 + '개조 가능' 표시가 붙은 설비 칸만 개조. 핵심 구조(엔진 자리, 장갑)는 개조 불가 |
| 배치 | 월드가 아니라 **배치 패널**에서 함(백팩 배틀즈, JumpSpace, FTL 전개도 참고). 패널은 아직 안 만듦 |
| 에셋 | 보유 에셋만 사용(AI 생성, 유료 팩 불가). `Assets/Imports` 원본은 수정 금지, 쓸 것만 복사하고 복사본 머티리얼만 URP Lit으로 고침 |
| 형식 1 | 구조층 1차 구현(아래 5.2)은 "동작과 출력 불변"으로 동결. 새 모델은 별도 경로로 만듦 |

**사용자가 정하지 않은 것**: 계획서의 열린 질문은 **없음**. 옛 4번(모듈이 걸음을 막는가)과 6번(완전히 끊기는 배치)은 사용자가 결정함(위 표). 나머지(분리된 모듈은 보관함으로, 분리된 블록은 버림, 접합 방칸↔방칸은 열린 변, 블록 회전은 D 뒤)는 AI가 추천대로 정해서 12.2절 "결정됨"에 있음.

## 4. 모델 요약 (계획서를 안 읽는 사람용)

- **블록** 하나는 자기 윤곽, 가압구역(통로 칸과 방칸), 설비구역, 접합부를 한 덩어리로 가짐. 문자 격자(텍스트 파일)로 정의함.
- **모듈**(조종석, 치료 베이, 재배 베이 등)은 블록과 별개로 저장되고, 이어진 블록 전체의 방칸 합집합 위에 놓임. 회전 가능.
- **프리셋**이 초기 우주선임: "어느 블록을 어디에 붙였고, 어느 모듈을 어디에 놓았는가"의 목록.
- **방은 저장하지 않고 계산함**(벽과 닫힌 문으로 막힌 칸 덩어리). 방 이름은 놓인 모듈이 정함.
- **접합부**는 두 블록이 맞닿는 곳이고 분리 지점임. 변 상태(없음, 벽, 문, 차단막)는 변마다 주인이 하나이며 접합 변은 접합부가 가짐.
- 데이터는 "배치 데이터 한 덩어리 → 생성기 → 3D" 구조여야 함. 씬에 손으로 놓은 방과 벽에 의존하면 패널이 못 붙음.

A0 격자(`Ship01_1a.txt`)는 새 파서로 못 열고 비교 기준으로만 남음.
