# 씨앗 플레이테스트 웹 게임 계획

계획서일 뿐이고 1단계만 구현함(사용자 승인, `Tools/SeedGame/`). 2단계 이후는 아직 아무것도 만들지 않았음. 사용자 승인 전에는 구현하지 않음.

작성 2026-11-24. 비평 세 번, 사용자 정정(시간 모델)과 범위 결정 뒤 고쳐 씀. 숫자는 지도 스크립트(`Tools/SeedMap/seedmap.py`)의 모델을 읽기 전용으로 불러 센 값임. 파서가 읽은 값이지 문서의 의도가 아님. "본부 세션"은 이 계획을 맡긴 상위 작업 세션을 뜻함.

## 한눈에

- 씨앗 306개를 "시간이 흐르면 사건이 터지고, 그 순간의 능력으로 풀고, 안 풀면 나빠지는" 브라우저 게임으로 돌려 **씨앗 지도가 실제로 굴러가는지** 검증함. 1순위는 검증이고 재미 판정이 아님.
- **보는 것은 하나뿐**(사용자 결정): 특정 사건이 터졌을 때 해결할 능력(선체, 내 몸, 드론, 물건 전부)이 있는가. 수리, 우주선 모딩(모듈 배치, 선체 개조), 자원 관리(채취, 창고, 정제)는 화면과 규칙에서 뺌.
- **레퍼런스는 "80억분의 1"**(1in8b.life, 인생 시뮬레이션). 본부 세션이 사이트 첫 화면을 읽어 확인한 사실: 무작위로 태어난 한 인생을 시간이 자동으로 흐르는 채로 지켜봄(배속과 일시정지가 있음). 나는 사이트를 직접 읽지 않았음. **차용하는 것은 "시간이 알아서 흐른다" 하나뿐**임(사용자).
- **시간 모델**: 깨어 있는 동안 시계가 초 단위로 알아서 흐르고 사건이 시간에 따라 떠오름. 시간을 빨리 보내는 정식 수단은 **동면 하나**이고 상한은 동면 수단의 단계가 정함. 분석, 설치, 배양은 같은 시계 위의 타이머이고 **끝나기 전에는 그 능력의 상태가 바뀌지 않음**.
- 데이터는 두 층임. **자동층**은 306개 전부를 문서에서 기계로 뽑음. **효과층**은 사이드카 파일에 일부만 둠(LLM 초안을 사람이 검토). 씨앗 문서와 지도 스크립트는 고치지 않음.
- 시기를 무시하면 출발 장비로 길이 하나 이상 열리는 씨앗은 248/306이지만 길 1464개 중 열리는 것은 402개뿐임. 예상되는 그림은 막힘이 아니라 **정체**임(정적 계산이고 플레이로는 확인 못 함). 시기까지 치면 출발·전시기에 뜰 수 있는 씨앗은 24개뿐임.
- 이 웹 게임은 유니티보다 먼저 도는 **규칙 실험실**임(사용자 결정). 유니티와 공유하는 것은 **사건 조건과 효과 스키마뿐**임. 유니티와 QuestMap이 쓰는 QSD JSON으로 바꿔 내보내는 일은 이 계획 범위 밖이며 승인 사항임. 6단계 + 선택 단계 하나(7. 2D 선체 평면도, 보기만). 가장 비싼 것은 5단계(효과층)임.
- **정보는 단계로 드러남**(사용자 원칙): 씨앗 지도는 내용을 다 보이지만 플레이에서는 처음에 표면의 질문과 일반 선택지만 보이고, 사정과 길은 가진 검토 능력만큼 드러나며, 드러난 뒤에도 요구를 채운 길만 보임. 잠긴 길까지 다 보이는 **작성자 보기**는 검증용 토글이고, 검증 판정은 작성자 보기와 봇이, 취향 판정은 플레이 보기가 맡음. 공개 단계는 유니티와 공유하는 사건 스키마에 들어감(유니티 구현은 이번 범위 아님).

## 1. 문제

| 문제 | 근거(실측) |
|---|---|
| 씨앗이 언제 나오는지 적혀 있지 않음 | 00_Means 설계 결정 7번이 "가진 상태(테크, 시기, 선택)가 조건"이라고 정했지만 형식 필드가 없음. 시기 줄만 있음(시기가 둘 이상인 씨앗 179개, 출발·성간·전시기를 포함하는 씨앗 160, 출발·전시기만 24) |
| 결과와 엮임이 산문이라 게임 효과로 쓸 수 없음 | 길 1464개, 본문 평균 약 205자. 엮임에서 길↔후속을 짝지을 수 있는 것은 "…로 푼 배는" 꼴만 세면 43/306(정규식을 넓히면 49) |
| 수단을 얻는 길이 문서에 거의 없음 | "남는 것"에 수단 이름이 나오는 것은 370종 중 34종. 씨앗에 쓰이는 수단 225종 중 191종은 어떤 길의 결과에도 이름이 없음. **동면 수단 5종은 요구로는 15/12/11/12/6곳 쓰이지만 결과에는 0/5** |
| 출발 장비로는 길 폭이 좁음 | 출발 장비 34종(물건은 내력 아무거나 허용, 시기 무시)으로 길이 하나라도 열리는 씨앗 248/306, 열리는 길 402/1464. 출발 장비 밖 수단이 필요한 길 988개, 상태 요구로 닫힌 길 74개. 정의를 바꾸면: 상태 요구 없는 길만 127/306, 새 수단 중 출발 시기 6종을 더하면 249/306, 3.3의 시작 내력 제안이면 240/306 |
| 상태 전이 규칙이 없음 | 상태 사전도 "무엇이 무엇을 대체하나"도 없음. 상태 요구는 낡음 73, 대체됨 61(길로는 57), 연구 중 49(길 48), 탑재 중 44, 배양 중 33, 미분석 19, 연구 완료 18, 고장 7 |
| 씨앗의 시간 낱말이 게임 시간이 아님 | 징후 줄에 "며칠"이 든 씨앗 279/306. "하루", "한 사이클"도 쓰임. 컨셉 18장 제안 8번은 이를 시계 위의 길이 상수로 옮기자고 함 |
| 동면 상한과 시계 범위가 넓음 | `TechExamples.md`: 저온 동면 포드(출발) "상한 100년", 정밀 동면 포드(성간) "상한 수만 년", 최소 존재(별의끝, 5장) "상한 없음". 시간 지연 정박(거대공학)과 꿈 동면(초월)은 상한이 적혀 있지 않음. 시기 표의 별의끝은 1000억~100조 년이고 암흑은 그 뒤라 시계는 1e14년 너머까지 감 |
| 이름과 내력 철자가 흔들림 | 편지 "안 읽음" 2 / "읽지 않음" 8. 상태가 아닌 꼬리표 56건(다 자람 10, 친밀 높음 8, 방문마다 적음 8 등). "주사위"(정의 없음)와 "주사위 한 쌍"이 따로 있음 |
| 방치가 한쪽으로 쏠림 | 나빠짐 152, 섞임 91, 잦아듦 62, 좋아짐 1 |
| 기존 검사로는 못 보는 것 | 지도 검사(`seedmap.py check`)는 문서 모양만 봄. 도달 가능성, 수단 획득, 판에서의 정체는 플레이해야 보임 |

| 1. 데이터 | A 마크다운만 / B 씨앗 문서에 필드 추가(**사용자 승인 사항**) / C 사이드카 / D 자동층 306 + 사이드카 효과층 |

## 3. 선택과 이유

| 질문 | 선택 | 이유 | 버린 것 |
|---|---|---|---|
| 1 데이터 | **D** | 첫날부터 306개가 뜨고, 효과층 없이는 길 폭이 안 늘어나는 것이 화면에 바로 드러남 | B는 열린 질문 5 |
| 1 효과층 1차 | **05 물체 묶음 20개** | 씨앗이 가장 적어(20) 검토 비용이 가장 적고, 출발 장비로 열리는 비율이 둘째로 낮음(14/20=70%. **가장 낮은 것은 01 25/42=60%**, 1단계에서 다시 세어 정정함). 03 신앙(39/42)은 이미 거의 다 열림 | 01은 비율이 더 낮고 비용은 두 배. **05 유지 여부는 사용자 확정 대기** |
| 1 등장 조건 | **기본 (가), 토글 (나)와 (다)** | (가)는 검증 기준선. "뜨는데 고를 길이 없음"은 여기서만 잼. (나)가 설계 결정 7번에 가장 가까움 | 판 비교로 정함 |
| 2 시계와 행동 | **자동 시계 + 동면 빨리감기. 행동은 시계를 건너뛰지 않음** | 사용자 정정. 방치가 "시간이 흘러 나빠지는 것"으로 이어짐. 행동이 시계를 건너뛰면 또 하나의 빨리감기가 되므로, 행동은 시계 위에서 "진행 중"으로 흐르고 도중에 뜬 사건도 처리됨. 이러면 "정식 빨리감기는 동면뿐"과 맞음 | 행동 점수(비교 토글로만) |
| 2 동면 | **18장 제안 최소판, 길이 직접 고름, 상한은 동면 수단 단계, 동면 능력은 시기 진입 때 지급(검증용, 보급과 별개로 기본 판에서 켬)** | 씨앗 결과로는 동면 능력을 못 얻어(0/5) 보급을 끈 기본 판이 출발 상한에 갇힘. 지급 규칙은 진행을 위한 장치일 뿐이고, "씨앗이 동면 능력을 주지 않음"은 보고서의 별도 발견으로 냄 | 보급에 기대기(기본 판이 보급을 끄므로 안 됨) |
| 2 정보 공개 | **단계 공개, 플레이 보기는 가능한 길만, 작성자 보기는 토글.** 사다리 데이터는 **(다)**: 자동층은 엄격 규칙, 5단계부터 사람 확인 | 사용자 원칙. 이전 기본안(잠긴 길을 크게 띄우고 "이게 있었으면")은 원칙과 반대라 뒤집음. "왜 못 고르나"는 작성자 보기와 보고서가 맡음 | 다 보임, (가)만, (나)만 |
| 3 | **능력 목록**, 얻기는 씨앗 결과 + 보급. **기본 검증 판은 보급을 끈 판** | 사용자: 능력마다 상태, 남은 시간, 언제 가동되나가 보여야 함. 보급을 켜면 "얻을 수 없는 수단"이 거의 다 지워짐 | 나무 그림 |
| 4~6 | **시드 + 행동 로그(필수) + localStorage와 JSON. 봇 N판 + 보고서. 지도 스크립트를 불러 씀. 엔진 JS 하나** | 재현에 시드가 필요함. 랜덤, 시기, 방치가 섞여 정적 계산만으로는 정체가 안 보임. 파서와 엔진을 하나씩만 유지. 엔진은 node로도 돌게 둠(이 PC에 v24, 필수 아님) | 지도 스크립트 수정 |

### 3.1 씨앗 한 장의 모양 (질문 1)

| 필드(QSD 대응) | 어디서 | 층 |
|---|---|---|
| 열쇠(`id`), 지문(없음) | 열쇠는 묶음 번호 + 제목(지도 모델의 씨앗 번호는 파일 안 순서라 밀려서 안 씀). 지문은 제목, 길 이름, 요구, 길 본문을 이은 해시로 낡은 사이드카를 잡음 | 자동 |
| 조건(`when`) | 시기를 연도 구간으로 바꾼 것(3.2) + (나)나 (다) 토글 + 사이드카의 플래그 조건 | 자동 + 효과 |
| 노리는 곳(`targets`) | 씨앗 머리 줄(배, 나, 일손, 앎). 피해가 가는 축이고 평면도의 방(3.7)과 다른 축 | 자동 |
| 징후 1, 2(`signs`), 걸림돌(없음) | 징후 줄을 "며칠"에서 자름(279/306). 두 번 나오는 6개는 첫 번째에서 자르고 목록으로 냄. 징후 1, 징후 2, 사정, 걸림돌, 길이 각각 어느 공개 단계에 속하는지는 3.2a를 따름 | 자동 |
| 언제 드러나나(`phase`) | 씨앗에 정보가 없어 계산해서 채움: 깨어 있는 동안 뽑히면 awake, 동면 중 생기면 wake, 그중 깨움 규칙(3.2)에 걸리면 sleep | 자동 |
| 공개 단계(없음), 검토 사다리(없음) | 무엇이 어느 단계에서 보이나, 어떤 능력이 사정을 여나(3.2a). 자동층은 규칙 초안, 효과층에서 사람이 확인. **유니티와 공유하는 사건 스키마에 들어가는 새 필드** | 자동 + 효과 |
| 길(`responses`의 `label`, `needs`, `text`) | 이름, 요구, 과정, 결과 글. **요구 채움**: 그 순간 수단의 상태가 요구 상태와 같으면 채움. 상태 표기가 없는 요구는 가동만 채움(**낡음은 안 채움**, 시대가 넘어가 낡아서 줄어든 폭은 보고서에서 따로 셈). **탑재 중 요구는 예외**: 가동이면 채우고, 고를 때 하루를 더 쓰며 그동안 그 수단의 본래 쓰임이 멈춤. 물건은 내력이 같아야 함(별칭 표를 거침). 플레이 보기에서는 사정이 공개된 뒤 채운 길만 보임 | 자동 |
| 길의 효과(`effects`) | 능력 얻음(미분석으로), 잃음, 상태 바뀜, 내력 바뀜, 게이지 증감, 플래그 켬, 후속 예약 | 효과 |
| 맨손, 방치(`ignore.tone`) | 맨손의 자동 효과는 노리는 곳 게이지 감소 하나. 방치는 첫 낱말로 결을 정하고(나빠짐 worse, 섞임 mixed, 잦아듦 fade, 좋아짐 better, 1:1) 결에 따라 노리는 곳 게이지를 움직임 | 자동 |
| 후속(`draw: followup`), 검토(없음) | 자동층은 엮임의 따옴표 제목, 어느 길이든 풀면 가중치가 오름. 효과층은 길별로 짝짓고 반드시 옴 / 검토는 안 됨·됨·보류, 사람만 바꾸고 게임은 "됨"만 씀 | 자동 + 효과 |

**후처리 규칙**(지도 모델 위에서): 징후 자르기, "→ 결과"와 "남는 것" 가르기, 방치 첫 낱말 읽기, 별칭 적용, 지문 계산. 처리 못 한 씨앗은 목록으로 냄. **사이드카가 낡으면** 그 씨앗은 자동층으로만 뜨고 빨간 목록에 오름. 열쇠가 안 맞으면 "주인 없는 사이드카"로 따로 뜸. 비슷한 제목에 붙이는 추측은 안 함. **효과층**: LLM이 닫힌 효과 낱말과 수단 목록 안의 이름으로만 초안을 냄. 목록 밖 이름이면 내보내기 실패. 사람이 표로 보고 "됨"을 누름.

**QuestSystemDesign(이하 QSD)과 어긋나는 곳과 다시 닿는 곳**

| 항목 | 이 계획 | 이유 |
|---|---|---|
| 요구, 더해진 필드 | 수단 상태와 내력이 들어감(QSD는 테크 보유와 상태값). 지문, 걸림돌, 검토가 더해짐 | 씨앗의 길이 그렇게 적혀 있음. 사이드카 관리와 검토 단계 |
| 못 고르는 길 | 플레이 보기는 공개된 것 중 채운 길만 보임. **못 채운 길이 안 보인다는 점에서만 QSD 3장과 같음**(QSD 3장에는 공개 단계가 없음). 작성자 보기만 잠긴 길까지 보임 | 사용자 원칙. 작성자 보기는 검증용 |
| 자동층 후속 | 가중치만 올림(QSD의 followup은 반드시 옴) | 짝이 43/306뿐임. 효과층 짝만 반드시 옴. **QSD 14장 3번**에 두 판 비교로 답을 줌 |
| `phase` | 이제 계산해서 채움 | 동면이 들어와 어긋남이 줄어듦 |
| 긴장 예산 | 깨어 있는 동안은 열린 일 한도. 동면 중 사건 수는 "시대 계수 × 이번 동면 조각 길이의 로그"를 기대값으로 확률로 뽑음 | **QSD 8장과 다름**: QSD는 흐른 해 **전체**의 로그로 예산을 세고 사건마다 부담(load)을 빼는데, 씨앗에 부담 값이 없어 이 계획은 이번 동면 길이만 봄. 열린 일 한도는 **14장 5번**에 답을 줌 |
| 방치 기준 | 자지 않아도 "며칠" 상수마다 방치를 침. 동면 한 번은 방치 차례 한 번으로 셈(3.2). 감지 못 해 바에 안 뜬 동면 사건도 방치함 | **QSD 14장 4번**의 바탕은 "드러났는데 대응하지 않고 잤다"임. 자동 흐름에서는 시간이 지나는 것이 곧 방치라 넓힘. 못 본 것도 친다는 쪽은 18장 제안 4와 맞음 |
| 설치 | 모든 설치가 타이머로 흐름 | 컨셉 18장 [확정]은 "내가 직접 설치해야 하는 것을 안 했으면 그대로 남는다"임. 직접 설치는 걷기와 조작이라 범위상 줄임 |
| 동면 도중 끊기 | 깨움 사건으로 강제로 깨는 것만 | **14장 8번**은 열어 둠 |
| 상태값, `cost` | 미리 선언하지 않음(게이지 4개, 수단 상태, 내력, 플래그). 비용은 시간만 | 씨앗에 줄기 단계값이 없음. 자원 관리는 범위 밖. 14장 6번은 시간 쪽만 답을 줌 |
| `place`(곳) | 7단계 전까지 없음 | 7단계에서 사이드카의 "방" 필드로 채움 |

### 3.2 시간 모델, 타이머, 동면, 씨앗의 생애 (질문 2)

**한 시계.** 사건 엔진은 시뮬레이션 시계 위에 "다음에 일어날 일과 그 시각" 목록(사건, 타이머 끝, 방치 차례, 후속, 행동 끝)을 두고 시각 순서대로 처리함. 같은 시각이면 목록에 먼저 들어간 일부터, 그 시각의 플레이어 행동은 그 뒤에 처리함. 화면은 실시간 배율로 보여 주고 봇은 기다림 없이 최대 속도로 돌림. 규칙은 벽시계에 기대지 않음. **개발용 배속과 일시정지는 검증 토글이고, 플레이어의 정식 빨리감기는 동면뿐.** 화면이 안 보이는 동안(뒤 탭)은 기본이 몰아 처리(일 목록 순서대로라 결과가 같음), 토글로 멈춤. 어느 쪽이 맞는지는 3단계 판정 거리이고 열린 질문 1과 겹침.

**시각의 표현.** 모든 시각은 (정수 연, 그 해 안의 초) 짝임. 더할 때마다 초가 한 해를 넘으면 연으로 올림. 그래서 1e14년에서도 초 단위 타이머가 제 순서에 끝남. 연도 상한 노브를 두어 정수 연이 실수의 정수 안전 범위(약 9e15)를 넘지 않게 함(최소 존재는 상한이 없어 막지 않으면 넘을 수 있음).

| 구간 | 일어나는 일 |
|---|---|
| 깨어 있는 동안 | 시계가 초 단위로 흐름(날짜를 세지 않음). 평균 뽑기 간격마다 조건이 맞는 씨앗을 가중치 랜덤으로 뽑음(열린 일 한도가 차면 안 뽑음). 효과층 후속은 예약 시각에 옴. **방치 규칙(하나)**: 모든 열린 일은 생긴 시각부터 방치 시계가 돌고, 손대지 않은 채 "며칠" 상수가 지날 때마다 방치 차례 한 번. 다만 동면 구간 안에서는 몇 년이 지나든 차례를 한 번만 셈. 그래서 잠들기 직전 사건과 잠든 직후 사건이 같은 값을 치름 |
| 행동 | 검토(3.2a), 길이나 맨손, 타이머 시작(분석, 설치, 배양), 내력 손질(되돌릴 수 없음). 행동은 시간을 건너뛰지 않고 그 길이만큼 시계 위에서 "진행 중"으로 흐름. 한 번에 하나. 도중에 사건이 뜨면 뜬 채로 처리됨. 길의 기본 길이는 "하루" 상수, 탑재 중 길은 하루를 더 쓰고 그동안 그 수단의 본래 쓰임이 멈춤. "하루" 상수는 이야기 속 하루가 아니라 화면에서 기다릴 만한 짧은 시계 길이로 두는 노브임 |
| 타이머 | 능력마다 따로 돎(수 초부터 수억 년, 컨셉 8장). 깨어 있을 때도 동면 중에도 같은 시계. 끝나는 시각에 상태가 바뀌고 그 전에 터진 사건에는 바뀌기 전 상태로만 쓰임 |
| 동면 들어감 | 길이를 고름. 상한은 가진 동면 수단 중 고장이 아닌 것의 가장 높은 단계가 정함(낡음은 그대로 씀). 전부 고장이면 "응급 동면 길이" 노브만큼은 잘 수 있음(판이 멈추지 않게). 깨어 있는 시간 상한에 닿으면 강제로 동면에 들어감(길이는 마지막에 고른 값, 없으면 상한). 열린 일은 위 방치 규칙대로 이번 동면에서 방치 차례를 한 번 받음 |
| 동면 중 | 구간을 시대 경계로 나누고, 조각마다 사건 수를 "시대 계수 × 조각 길이의 로그"를 기대값으로 한 번 뽑고 시각들을 조각 안에서 뽑아 정렬함. 1년 미만 동면은 기대값이 1 아래라 확률로 0이나 1개. 시계는 그 시각들로만 건너뜀. 사건은 바에 하나씩 나타났다 사라짐(18장 제안 3). 감지·기록 능력이 잡은 것만 바에 뜸(제안 4. 자동 규칙: 감지 갈래 능력이 가동이면 확률이 오름. **근거 약함**). 시기에 들어서면 그 시기의 동면 수단을 가동으로 지급(검증용 규칙) |
| 깨움과 깨어난 뒤 | 깨움 규칙에 걸린 사건이 생기면 바가 멈추고 깸(phase sleep). 자동 규칙: 방치 결이 나빠짐이고 노리는 곳에 배가 있는 씨앗. 이에 걸리는 씨앗 103/306. **근거 약함**(씨앗에 급함 표시가 없음). 깨어나면 요약이 같은 바에 남음(제안 1). 동면 중 생긴 사건도 같은 방치 규칙을 따르고(이번 동면 차례 한 번), 잦아듦과 좋아짐이 아니면 깨어난 뒤 열린 일로 뜸. 바에 안 뜬 것은 "동면 중 생김, 못 봄" 표시. 열린 일 한도를 넘으면 가장 오래된 것부터 방치 효과 한 번 주고 닫음 |
| 판 끝 | 종료 노브 중 먼저 닿는 것: 최대 사이클 수, 연도 상한, (토글) 게이지 바닥 |

**봇이 고르는 때**: 사건이 뜰 때, 행동이 끝날 때, 깨어난 직후. 그때 정책이 행동 하나나 "동면(길이)"를 고름. 열린 일이 없거나 할 수 있는 행동이 없으면 동면함. 깨움 대상이 103/306이라 "상한까지 잠" 정책은 거의 끝까지 못 잘 것으로 봄(확인 못 함).

사용자가 말한 "처음 10년"은 문서의 100년과 다름. 문서 값 그대로면 정밀 포드 수만 년으로 거대공학(수억 년)까지 가려면 수천~만 번을 자야 해서 사실상 못 감. 그래서 4단계 판정 판과 봇 기본 판은 **"상한 계단" 노브**(시기마다 다음 시기에 닿을 만한 상한을 강제로 준 검증용 값)로 돌리고, 문서 값 판은 비교용임. 전부 사용자가 확정함(열린 질문 2). 육체 이탈(거대공학)은 "동면이 필요 없어진다"라서 이 표에 넣지 않음.

**18장 제안에서 1차로 가져오는 것**: 1(바 두 모드), 2(눈금 단위가 동면 길이에 맞춰 바뀜), 3(하나씩, 깨울 때 멈춤), 4(감지한 것만), 8(시간 낱말을 시계 상수로). 6(수단이 모듈 상태로 보이고 그 곳에 가서 씀)은 7단계 상태색에서 보이는 쪽만 가져옴. **안 가져옴**: 5(막아 낸 일 표시, 효과층 뒤), 7(선체 칸이 모듈 수를 한정함, 모딩이라 범위 밖), 6의 "가서 씀"(걷기라 범위 밖). 피곤과 잠(18장 확정)도 범위 밖이고 "깨어 있는 시간 상한" 노브로 대신함(피곤 판정은 유니티 프로토타입 몫).

**게이지와 보급**: 게이지 4개(나, 배, 일손, 앎)는 수리가 없으니 **피해 기록**이 됨. 방치와 맨손이 깎고 효과층의 길 효과만 올림. 기본 판은 바닥나도 끝나지 않음. **약한 곳**: 그래서 기본 판에는 게이지 압박이 0이고 봇 정책끼리의 차이가 게이지로는 안 드러남. "바닥이면 끝" 토글 판을 같이 돌림. 보급은 자원이 아니라 능력 하나를 미분석으로 주는 사건이라 남김.

### 3.3 능력 목록 (질문 3)

- 화면: 능력마다 갈래, 상태, **남은 시간, 언제 바뀌나**(시뮬레이션 시각과 지금부터의 길이), 물건은 내력. 누르면 그 능력을 요구하는 길과 씨앗 목록. 지금 쓸 수 있는 것과 타이머 중인 것이 한눈에 갈려야 함. 출발 장비는 본표 21종(가동) + 물건 13개.
- 시작 내력(제안, **사용자 확인 필요**, 열린 질문 4): 장난감 분해 안 함, 편지 읽지 않음, 손목시계 한 번도 안 멈춤, 종이 책 메모함, 일지 빠짐없이 씀, 악기 계속 침, 사진 넣어 둠, 첫 드론의 껍데기 그대로 둠, 화분 한 번도 안 끊김, 공구 계속 씀, 주사위 눈이 닳음, 술 안 땀, 녹음 자주 들음. 00_Means 표에는 편지("읽음"만)와 술("땀"만)의 반대쪽 값이 없어서 첫 값을 고르면 그 길이 시작부터 닫힘. 이 제안으로 열리는 씨앗은 240/306(편지 "안 읽음"을 별칭으로 묶을 때, 안 묶으면 239, 시기 무시). 반대쪽 내력은 되돌릴 수 없는 손질로만 감. 봇 판은 노브 하나로 시작 내력을 무작위로 굴림.

| 전이(제안, 문서에 없음) | 언제 |
|---|---|
| 미분석 → 연구 중 → 연구 완료 → 가동, 배양 중 → 가동 | 분석 타이머 시작(연구 중), 끝나는 시각에 연구 완료. 설치 타이머, 배양 타이머(기르는 것만)가 끝나는 시각에 가동 |
| 탑재 중 | **상태로 두지 않음.** 길을 고를 때 드는 값(설계 결정 5번) |
| 가동 → 낡음, 가동 → 대체됨 | 동면 중 시대가 넘어갈 때 확률로 / 대체 관계 표에서 이 수단을 대체하는 수단을 얻었을 때 |
| 가동·낡음 → 고장 | 방치 효과나 길의 "잃음"으로만. 수리가 없으니 **되돌릴 수 없음**. 고장 상태를 요구하는 길 7개에만 쓰임 |

**대체 관계**는 문서에 없음. 기계가 "같은 갈래이고 시기가 더 뒤인 수단"을 후보로 내고 사람이 확정함. 확정 전에는 대체됨 길 57개가 못 열림. 약한 곳임. **별칭 표**는 물건 내력 철자, 비물건 꼬리표 56건, 수단 이름 흔들림까지 다룸. "주사위"를 "주사위 한 쌍"으로 볼지는 사람이 정하고 그 전까지는 경고.

### 3.4 저장과 재현 (질문 4)

- 재현은 시드 + 행동 로그가 필수임. **행동의 시각은 시뮬레이션 시계 기준으로 적고, 난수는 일 목록을 처리하는 순서로만 씀**(동면 조각의 사건 수와 시각 뽑기도 같은 순서 안). 화면 프레임, 실시간 배율, 개발용 배속·일시정지, 뒤 탭과 무관해야 함. 그래서 같은 시드와 로그면 느리게 본 판, 배속으로 본 판, 봇이 최대 속도로 돈 판의 일지가 글자 하나 다르지 않아야 함. 사람이 실시간으로 둔 판의 로그를 봇이 다시 틀어도 같아야 함.
- localStorage 자동 저장과 JSON 공유는 편의임(씨앗별 지문 목록 포함). 데이터가 바뀐 뒤 옛 저장을 부르면 바뀐 씨앗과 사라진 씨앗을 빨간 목록으로 띄우고 "낡음으로 표시하고 계속"이나 "판 버림"을 사람이 고름. 조용히 이어 가지 않음.

### 3.5 검증 보고서 (질문 5)

| 항목 | 뜻 | 지도 검사가 보나 |
|---|---|---|
| 한 번도 안 뜬 씨앗, 시기 미도달 | 닿은 시기 안에서 N판 동안 조건이 한 번도 안 맞음 / 판이 그 시기에 닿지 못해 뜰 수 없었음(따로 셈) | 못 봄 |
| 뜨는데 고를 길이 없는 씨앗 | 터진 순간의 상태로는 맨손 말고 전부 잠김인 비율. **(가) 시기만 기준선 판에서 잼.** 타이머 중이라 못 쓴 경우를 따로 셈 | 못 봄 |
| 검토 때문에 영영 안 열린 씨앗과 길 | 분모는 정책별로 **그 판에서 뜬 씨앗**. 검토를 시도한 씨앗만으로 "능력이 없어 멈춤"을 세고, 검토를 안 한 것은 따로 셈(늘 맨손·늘 방치 정책 판은 이 항목에서 뺌). 공개 단계별 도달률, 못 알아봄으로 닫힌 씨앗, 사다리가 규칙인지 사람 확인인지 표시 | 못 봄 |
| 수단 얻는 경로 | 씨앗 결과로 얻음 / 보급으로만 / 지급 규칙으로만 / 못 얻음. 시기 칸이 없는 24종 중 물건 13은 출발 장비라 제외, 물체 9는 씨앗 결과로만, 정의 없는 2종은 경고. **별도 발견: 동면 능력을 주는 씨앗 결과가 없음(0/5)** | 못 봄 |
| 도달 못 하는 (수단, 상태), 막다른 줄기 | 그 상태로 가는 전이가 없음 / 지난 후속, 시기가 안 맞는 후속 | 못 봄 / 끊긴 제목만 봄 |
| 길 폭의 흐름 | 사이클마다 "지금 시기에 뜰 수 있는 씨앗의 길" 중 두 값: **작성자 기준 폭**(채운 길) / **플레이 공개 폭**(공개되어 보인 길). 낡음 때문에 줄어든 폭은 따로 셈. 시작 값에서 안 늘면 정체 | 못 봄 |
| 방치 결과 게이지 | 실제로 맞은 결과 축. 깨어 있을 때와 동면 차례를 나눔 | 문서 안 개수만 |

- 봇 정책 네 가지: 무작위, "검토 먼저, 그다음 보이는 길 중 요구를 가장 많이 채운 쪽"(둘 다 검토함), 늘 맨손, 늘 방치(둘 다 검토 안 함). **봇은 엔진이 넘기는 공개 상태 뷰만 받음**: 표면 문구, 공개된 필드, 보이는 길의 이름과 요구, 능력 목록, 지금 시각. 봇은 공개된 뒤에도 글 본문을 결정에 쓰지 않음. 동면 길이도 정책마다(짧게, 상한까지). 고정 시드로 N판. 기본은 보급 끔 + 지급 규칙 켬 + 상한 계단. 비교 판: 보급 켬, 조건 (나), 게이지 끝 토글, 문서 값 상한.
- 보고서는 HTML 표 + JSON. 줄마다 묶음 파일 이름과 씨앗 제목. 지도에 겹쳐 보이는 일은 지도 스크립트 수정이라 범위 밖, 승인 사항. 규칙의 정의는 같은 규칙을 두 번 구현해서는 검증되지 않으니 사람이 고른 씨앗 몇 개를 판에서 확인함.

### 3.6 위치와 기술 (질문 6)

- `Tools/SeedGame/`에 내보내기 스크립트, 사건 엔진 파일, 화면 템플릿, `sidecar/`(효과층, 출발 장비와 시작 내력, 별칭 표, 대체 관계 표, 시간 상수, 동면 단계 상한), bat 파일(열기, 감시). 내보내기 스크립트는 지도 스크립트의 모델 만드는 부분을 불러 자동층을 만들고 사이드카를 합쳐 검사한 뒤 지도와 같은 방식(템플릿의 데이터 자리에 끼워 넣기)으로 HTML 한 장을 씀. 엔진은 규칙, 시계, 봇이고 외부 라이브러리가 없으며 화면 없이도, node로도 돎(선택 경로). 지도 모델의 키가 없으면 어느 키인지 말하고 멈춤. 만든 HTML은 커밋하지 않고 사이드카는 커밋함.

판정은 사용자가 화면을 보고 한 단어로 함(예: "됨", "밍밍함", "정체", "정신없음", "느림"). 단계마다 별도 리뷰 에이전트가 코드를 보고, 리뷰 없이 끝났다고 하지 않음.

| 단계 | 만드는 것 | 볼 화면 | 끝났다는 증거 |
|---|---|---|---|
| 1. 씨앗 하나 완주 | 내보내기, 사이드카 한 장(**"공짜 수리"**, `06_SpaceOpera.md`. 검토 능력은 제안: 비파괴 판독기나 분광 분석기, 사용자 확인), 사건 화면, 작성자 보기 토글, 수동 "방치로 닫기" 버튼 | 사용자 예시 그대로: 질문 → 그냥 둔다 / 검토한다 → 검토 능력이 없으면 "겉으로는 잘 되어 있는 것 같다"에서 멈춤 → 능력이 있으면 사정과 채운 길이 뜸 → 여파 → 일지 | **예시와 똑같이 도는 두 판의 스크린샷**(능력 없음, 능력 있음). 수동 버튼으로 일으킨 "못 알아봄" 일지. 씨앗 306 읽음, 후처리 실패 목록. 묶음별 출발 장비 열림 수와 사다리 있는 씨앗 수를 다시 세어 효과층 1차 묶음(05)을 확정 |
