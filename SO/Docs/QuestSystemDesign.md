# 퀘스트 체계 설계

작성일 2026-11-24. 수백 개의 퀘스트를 쓰고, 섞고, 한눈에 보고, 고치기 위한 체계다. 전제는 [GameConcept.md](GameConcept.md)를 따른다. 예시 원본은 [Quests/](Quests/README.md)에 있다.

이 문서에서 "확정"이라고 적지 않은 것은 전부 추천안이다. 14장에 정해야 할 것을 모았다.

## 1. 한눈에

- 퀘스트를 줄로 쓰지 않고 **사건 낱장**으로 쓴다. 한 장은 "배 어딘가에 생긴 변화 하나"다.
- 사건끼리는 서로를 직접 가리키지 않는다. 이름 붙은 **상태값**을 바꾸고 읽어서 이어진다. `따뜻한벽.단계 = 정체`라고 적어 두면, `따뜻한벽.단계 == 정체`를 조건으로 가진 사건이 다음에 온다.
- 같은 색으로 묶인 사건 무리를 **줄기**라고 부른다. 줄기는 보기 좋게 묶는 이름표일 뿐이고, 규칙은 사건과 상태값에만 있다. 그래서 1장짜리도 12장짜리도 같은 형식이다.
- 모든 사건에는 **방치 결과**가 있다. 놓치고 자면 나빠지는지, 저절로 잦아드는지, 오히려 좋아지는지를 적는다.
- 깰 때마다 무엇을 낼지는 **연출자**가 고른다. 림월드의 스토리텔러와 같은 역할이다.
- 자료는 JSON 글 파일이다. 게임이 실행 중에 읽으므로 폴더를 하나 더 두면 모드가 된다.
- **검사 도구**가 끊긴 연결을 찾고, **지도 도구**가 전체를 그림으로 보여 준다. 지도에서 바로 고치고 새로 만들 수 있다.

실제로 있는 것:

| 무엇 | 어디 |
|---|---|
| 예시 자료 (줄기 8개, 사건 29장) | `SO/Content/base/` |
| 검사 도구와 지도 도구 | `SO/Tools/QuestMap/` |
| 지도 여는 법 | `SO/Tools/QuestMap/퀘스트지도열기.bat`을 두 번 누른다 |

## 2. 세 가지 방식 비교

퀘스트를 만드는 방식은 크게 셋이다.

| | 단계 번호 방식 | 그림 그래프 방식 | 낱장 방식 |
|---|---|---|---|
| 대표 | 스카이림 | 킹덤 컴: 딜리버런스 | 림월드, 스텔라리스 |
| 한 퀘스트의 모양 | 번호표가 붙은 한 줄. 10, 20, 30처럼 번호를 올리며 나아간다 | 상자와 화살표로 그린 그림. 갈림길을 전부 그려 넣는다 | 모양이 없다. 조건이 맞으면 나오는 카드가 쌓여 있을 뿐이다 |
| 다음으로 넘어가는 법 | 대사나 스크립트가 "이제 30번"이라고 번호를 바꾼다 | 화살표를 따라간다 | 카드가 깃발(상태값)을 세우고, 다른 카드가 그 깃발을 본다 |
| 언제 시작하나 | 정해진 장소나 대화에서 | 정해진 장소나 대화에서 | 연출자가 조건 맞는 것 가운데 고른다 |
| 잘하는 것 | 손으로 짠 긴 이야기. 지금 어디까지 왔는지가 분명하다 | 한 사건을 푸는 여러 길. 한 그림에 다 보인다 | 수백 개가 서로 섞인다. 새 카드를 끼워 넣기 쉽다. 모드가 쉽다 |
| 못하는 것 | 퀘스트끼리 섞이지 않는다. 길이가 다르거나 갈라지면 번호가 꼬인다 | 수백 개가 되면 그림끼리는 여전히 따로 논다. 전용 도구 없이는 못 쓴다 | 전체가 한눈에 안 보인다. 깃발 이름을 틀리면 조용히 끊긴다 |

### 이 게임에 맞는 것

**낱장 방식을 바탕으로 하고, 나머지 둘의 장점을 도구로 가져온다.**

이유는 컨셉에 이미 있다.

- 이벤트는 선택지 창이 아니라 배의 상태 변화다. 낱장 하나가 "배 어딘가의 변화 하나"와 그대로 맞는다.
- 이벤트가 생기는 조건이 무작위, 시간, 테크, 선택 네 가지다. 넷 다 "어떤 값이 어떤 범위에 들어왔다"로 적을 수 있다.
- 시대는 챕터가 아니고 플레이마다 흔들린다. 번호 한 줄로는 적을 수 없고, 조건으로는 적을 수 있다.
- 테크는 꼬리표 붙은 카드이고 이벤트가 그 꼬리표를 찾는다. 낱장의 조건이 바로 그 일을 한다.
- 모드로 퀘스트를 더할 수 있어야 한다. 낱장은 폴더에 파일을 더하면 끝이다.

낱장 방식의 두 약점은 이렇게 메운다.

- **긴 이야기를 못 쓴다** → 스카이림의 단계 번호를 그대로 쓰되, 특별한 장치가 아니라 **상태값 하나**로 둔다. `함선AI.단계 = 3` 같은 식이다. 예시의 함선 AI 줄기가 이 방식으로 10단을 간다.
- **전체가 안 보이고 조용히 끊긴다** → 킹덤 컴의 그림을 손으로 그리지 않고 **자료에서 저절로 그린다**. 그게 지도 도구다. 끊긴 곳은 검사 도구가 찾아서 지도에 빨갛게 표시한다.

## 3. 사건 한 장

사건 한 장이 가지는 것이다. 파일에서는 영어 항목 이름을 쓰고, 지도 도구에서는 한국어로 보인다.

| 항목 | 지도에서 보이는 이름 | 뜻 |
|---|---|---|
| `id` | id | 이름표. `줄기.이름` 꼴. 겹치면 안 된다 |
| `thread` | 줄기 | 어느 줄기에 속하나. 색과 묶음을 정할 뿐이다 |
| `title` | 제목 | 사람이 읽는 제목 |
| `beat` | 박자 | 징후, 악화, 정체, 결판, 단발. 읽는 사람을 위한 표시다 |
| `draw` | 나오는 법 | `opener`는 연출자가 뽑아야 나온다. `followup`은 조건이 맞으면 반드시 온다 |
| `phase` | 언제 플레이어 앞에 나타나나 | 아래 표를 본다 |
| `place` | 곳 | 배의 어디에서 보이나 |
| `targets` | 노리는 곳 | 배, 나, 일손, 앎 |
| `when` | 조건 | 한 줄에 하나. 전부 맞아야 한다 |
| `weight` | 가중치 | 뽑힐 확률의 크기. `opener`만 쓴다 |
| `weightMods` | 가중치 보정 | "이 조건이면 몇 배". 테크 꼬리표에 따라 더 잘 나오게 할 때 쓴다 |
| `load` | 부담 | 0~5. 이 사건이 플레이어에게 얹는 짐. 연출자가 예산을 셀 때 쓴다 |
| `after` | 간격 | 같은 줄기의 앞 사건 뒤로 몇 번 깨고 나서 오나 |
| `repeat` | 되풀이 | 조건이 맞는 동안 다시 온다. 없으면 한 판에 한 번만 나온다 |
| `signs` | 징후 | `see` 보이는 것, `hear` 들리는 것, `panel` 상태 패널의 표시 |
| `responses` | 대응 | 플레이어가 할 수 있는 일의 목록 |
| `ignore` | 방치 | 아무것도 안 하고 잤을 때의 결과 |
| `note` | 메모 | 쓰는 사람을 위한 메모 |

`phase`의 세 값은 "이 변화를 플레이어가 언제 처음 마주치나"다.

| 값 | 뜻 | 예 |
|---|---|---|
| `wake` | 동면하는 사이에 이미 벌어졌다. 동면이 끝나고 일어나 돌아다니다가 발견한다 | 일어나 보니 창에 금이 가 있다 |
| `awake` | 깨어서 지내는 1~7일 가운데 어느 날 생긴다. 눈앞에서 벌어진다 | 밥을 먹는데 AI가 토마토 맛을 묻는다 |
| `sleep` | 동면 중에 생기고, 급해서 나를 도중에 깨운다. 비상 시스템이 켜진 채로 일어난다 | 예시에는 아직 없다 |

`sleep`은 컨셉 6장의 "문제가 되는 것만 턱 걸려서 플레이어를 깨운다"에 해당한다. 플레이어가 스스로 동면을 도중에 끊을 수 있는지는 아직 정하지 않았다(14장).

**징후는 꼭 있어야 한다.** 컨셉의 "징후는 항상 보이거나 들린다"를 형식이 강제한다. `see`와 `hear`가 둘 다 비면 검사에서 오류가 난다. `panel`에 "정상"이라고 적으면 "패널은 멀쩡하다는데 눈에는 이상하다"를 만들 수 있다.

대응 하나가 가지는 것:

| 항목 | 뜻 |
|---|---|
| `label` | 플레이어가 하는 일. "벽을 열어 본다" |
| `needs` | 요구. 조건과 같은 문법이다. 못 맞추면 이 대응은 뜨지 않는다 |
| `cost` | 드는 것. 지금은 글로만 적는다 ("부품 4, 하루") |
| `text` | 하면 무슨 일이 일어나나 |
| `effects` | 결과. 상태값을 바꾼다 |
| `rolls` | 확률로 갈리는 결과. `{weight, text, effects}`의 목록. 없어도 된다 |
| `ends` | 이 대응으로 줄기가 끝나면 `true` |

방치는 대응과 같은 모양에 `tone`이 하나 더 붙는다.

### 예시 한 장

```json
{
  "id": "따뜻한벽.정체",
  "thread": "따뜻한벽",
  "title": "벽 속의 것",
  "beat": "정체",
  "draw": "followup",
  "phase": "wake",
  "place": "복도",
  "when": ["따뜻한벽.단계 == 정체"],
  "repeat": { "cooldownWakes": 1 },
  "signs": {
    "see": "뜯긴 벽 안쪽에서 그것이 천천히 부풀었다 줄었다 한다.",
    "panel": "문제 있음, 고치는 법 모름"
  },
  "responses": [
    {
      "label": "떼어 낸다",
      "needs": ["따뜻한벽.크기 <= 1"],
      "text": "아직 작아서 손으로 뗄 수 있다. 그 방의 난방이 죽는다.",
      "effects": ["나.무드 -= 2", "따뜻한벽.결말 = 떼어냄", "따뜻한벽.단계 = 끝"],
      "ends": true
    },
    {
      "label": "전용 칸을 만들어 옮긴다",
      "needs": ["자원.부품 >= 4"],
      "text": "칸 안으로 옮기자 그것이 조용해진다.",
      "effects": ["자원.부품 -= 4", "따뜻한벽.단계 = 옮김"]
    }
  ],
  "ignore": {
    "tone": "worse",
    "text": "그것이 더 자랐다. 전력이 큰 만큼 샌다.",
    "effects": ["배.전력 -= 따뜻한벽.크기", "따뜻한벽.크기 += 1"]
  }
}
```

이 한 장에 들어 있는 것: 방치하면 `크기`가 1씩 큰다. 큰 만큼 전력이 샌다. `크기`가 2를 넘으면 "떼어 낸다"가 더는 뜨지 않는다. 단계가 그대로이므로 다음에 깨도 같은 사건이 다시 온다. 대신 끝까지 길들이면 큰 만큼 전력을 낸다(다음 장 `따뜻한벽.발전`).

## 4. 방치 결과

각 단계가 단서만 주고 끝나지 않게 하는 장치다. **모든 사건에 방치 결과를 적어야 한다.** 없으면 검사에서 오류가 난다.

`tone`은 네 가지다. 지도에서 점선의 색으로 보인다.

| tone | 뜻 | 색 | 예시 |
|---|---|---|---|
| `worse` | 나빠진다 | 빨강 | 창의 금이 가지를 친다. 벽 속의 것이 자란다 |
| `fade` | 저절로 잦아든다 | 회색 | 배관 소리가 작아진다. 칸 속의 것이 식는다 |
| `better` | 오히려 좋아진다 | 초록 | 드론이 돌을 더 가져오다가 유물을 가져온다. 침묵하던 AI가 생각을 마치고 돌아온다 |
| `mixed` | 좋은 것과 나쁜 것이 섞인다 | 노랑 | 벽이 따뜻해져 화분이 꽃을 피우지만 등이 어두워진다 |

`tone`은 사람과 지도를 위한 표시다. 실제로 무슨 일이 일어나는지는 `effects`가 정한다.

방치의 크기를 조절하는 방법은 세 가지다.

1. **숫자를 쌓는다.** `따뜻한벽.크기 += 1`처럼 방치할 때마다 숫자를 올린다. 뒤의 결과가 그 숫자를 쓴다(`배.전력 -= 따뜻한벽.크기`). 오래 방치할수록 크게 맞는다.
2. **대응의 문을 닫는다.** 대응의 `needs`가 그 숫자를 본다(`따뜻한벽.크기 <= 1`). 방치하면 쉬운 해결책이 사라진다.
3. **다른 길로 보낸다.** 방치했을 때와 대응했을 때 단계를 다르게 매긴다. 방치하면 `번짐`, 일찍 열어 보면 바로 `정체`로 간다. 준비한 사람은 한 단계를 건너뛴다.

방치가 좋은 결과인 사건을 섞어 두면 "전부 다 처리해야 하나"가 "무엇을 그냥 둘까"로 바뀐다. 컨셉의 "해로운지 이로운지 바로 알려 주지 않는다"와 맞는다.

## 5. 상태값

사건들이 함께 읽고 쓰는 이름 붙은 값이다. 전부 `states.json`에 미리 선언한다. 선언하지 않은 이름을 쓰면 검사에서 오류가 난다. 오타로 조용히 끊기는 일을 막기 위해서다.

### 종류

| 종류 | 뜻 | 예 |
|---|---|---|
| `flag` | 켜짐과 꺼짐 | `함선AI.생각마침` |
| `enum` | 이름 붙은 값 가운데 하나 | `따뜻한벽.단계`: 시작전, 번짐, 정체, 옮김, 끝 |
| `int` | 범위가 있는 정수. `min`과 `max`를 꼭 적는다 | `함선AI.자율성`: 0~10 |
| `number` | 큰 수 | `시간.년` |

단계는 숫자(`int`)로 써도 되고 이름(`enum`)으로 써도 된다. 짧은 줄기는 이름이 읽기 좋고, 긴 줄기는 숫자가 편하다. 예시에서는 함선 AI만 숫자를 썼다.

### 이름 규칙

`영역.이름` 꼴로 쓴다. 띄어쓰기는 없다. 한글을 쓴다.

| 영역 | 무엇 | 예 |
|---|---|---|
| `시간.` | 게임이 대는 시간 | `시간.년`, `시간.기상횟수` |
| `시대.` | 시대가 시작되는 해. 판마다 굴린다 | `시대.성간`, `시대.초월` |
| `나.` `배.` `일손.` `앎.` | 컨셉의 "어디에 쓰나" 네 축. 여러 줄기가 함께 건드리는 값 | `나.무드`, `배.전력`, `일손.드론마음` |
| `자원.` | 재고 | `자원.부품`, `자원.식량` |
| `<줄기>.` | 그 줄기만의 값 | `따뜻한벽.단계`, `따뜻한벽.결말`, `따뜻한벽.크기` |

줄기마다 관례로 두 개를 둔다.

- `<줄기>.단계`: 지금 어디까지 왔나. 기본값은 `시작전`(숫자면 0).
- `<줄기>.결말`: 어떻게 끝났나. 기본값은 `없음`. **다른 줄기가 읽으라고 남기는 값이다.**

### 주인

- `"owner": "game"`: 게임이 값을 댄다. 무드, 전력, 자원, 시간처럼 퀘스트 밖에서도 변하는 값이다. 사건이 읽고 바꿀 수 있다.
- 적지 않으면 퀘스트의 것이다. 사건만 이 값을 바꾼다.

### 시대가 흔들리는 법

`시대.초월` 같은 값에는 `"roll": { "base": 500000000, "spread": 0.25 }`를 적는다. 판을 시작할 때 5억 년의 앞뒤 25% 안에서 한 번 굴린다. 사건은 `시간.년 >= 시대.초월`이라고만 적는다. 그래서 같은 사건이 어떤 판에서는 5억 5천만 년에, 다른 판에서는 4억 년에 나온다. 고정된 구분선은 없다.

### 여러 줄기가 엮이는 방식

엮임은 세 가지 세기로 일어난다.

| 세기 | 방법 | 예시에 있는 것 |
|---|---|---|
| 약함 | 함께 쓰는 숫자를 올리고 내린다. 다른 줄기는 그 숫자를 **대응의 요구**로 본다 | 생일을 챙기면 `함선AI.친밀`이 오른다. 친밀이 4 이상이면 "짓고 있는 것"에서 AI에게 물어볼 수 있다 |
| 중간 | 함께 쓰는 숫자가 **사건의 조건**에 들어간다 | `일손.드론마음 >= 2`여야 드론이 스스로 짓기 시작한다. 드론 줄기 셋이 이 값을 올리고 내린다 |
| 강함 | 한 줄기의 `결말`이 다른 줄기의 조건이다 | `드론선물.결말 == 받아줌`과 `드론장례.결말 == 자리내줌`이 둘 다 맞아야 "짓고 있는 것"이 열린다 |

지도에서는 여러 줄기가 건드리는 상태값이 둥근 알약으로 따로 그려진다. 알약에 선이 많이 모일수록 그 값이 이야기의 교차로다.

**줄기를 섞고 싶으면 새 장치를 만들지 말고, 이미 있는 영역 값을 건드려라.** `나.무드바닥`, `함선AI.친밀`, `일손.드론마음` 같은 값이 많아질수록 서로 모르는 줄기끼리 저절로 엮인다. 줄기를 쓸 때마다 "이 줄기가 올리거나 내릴 만한 공용 값이 있나"를 한 번 묻는다.

## 6. 길이가 다른 줄기

전부 같은 형식이다. 다른 것은 사건의 장수뿐이다.

| 모양 | 어떻게 적나 | 예시 |
|---|---|---|
| 단발 | 사건 1장. 대응과 방치가 전부 `ends`다. 단계 값이 필요 없다 | 생일 |
| 되풀이하는 단발 | 위에 `repeat`를 더한다 | 생일 (6번 깰 때마다) |
| 2단 | 2장. 첫 장이 `단계`를 바꾸고 둘째 장이 읽는다 | 창의 금, 배관 속의 소리, 드론의 장례 |
| 4단 | 4장. 대응에 따라 단계를 건너뛸 수 있다 | 따뜻한 벽 |
| 10단 | 숫자 단계 하나로 줄을 세우고, 갈림은 다른 값으로 만든다 | 함선 AI (12장, 10단) |
| 갈라졌다 모이는 줄기 | 같은 단계에 조건이 반대인 두 장을 둔다 | 함선 AI 7단: `생각마침`이 켜졌으면 "생각의 결과", 꺼졌으면 "짧아진 말" |
| 결말이 여럿 | 마지막 장이 `결말`에 서로 다른 값을 쓴다 | 함선 AI: 도구, 내배, 승객, 동료 |
| 제자리에서 자라는 사건 | `repeat`를 켜고, 방치가 단계를 바꾸지 않는다 | 벽 속의 것, 줄지어 선 것들 |
| 두 줄기가 끝나야 열리는 사건 | 조건에 두 `결말`을 나란히 적는다 | 짓고 있는 것 |

두 줄기 관문은 이게 전부다.

```json
"when": [
  "짓는것.단계 == 시작전",
  "드론선물.결말 == 받아줌",
  "드론장례.결말 == 자리내줌",
  "일손.드론마음 >= 2"
]
```

셋이든 넷이든 줄만 더하면 된다. "둘 중 하나만 끝나도 열린다"는 한 줄에 `또는`을 쓴다.

### 징후 단계의 가지

줄기가 한 줄로만 흐르면 "보고, 방치하고, 다음 단계"의 되풀이가 된다. 그래서 **첫 장(징후)부터 가진 것에 따라 갈라지는 대응을 둔다.** 맞는 테크나 물건이 있으면 그 자리에서 되돌리거나 끝낸다.

첫 장에 둘 수 있는 가지는 네 가지다.

| 가지 | 요구 | 결과 | 예시 |
|---|---|---|---|
| 맨손 대응 | 없음, 또는 흔한 자원 | 다음 단계로 간다. 때로는 한 단계를 건너뛴다 | 벽을 열어 본다 |
| 되돌리기 | 테크나 물건 | 없던 일이 된다. 줄기가 끝난다 | 금속 프린터로 창을 새로 찍는다. 수리 드론이 벽 속의 덩어리를 떼어 온다 |
| 지름길 | 테크나 물건 | 대가 없이 뒤 단계로 간다 | 뇌 접속 장치로 배관 소리를 바로 알아듣는다 |
| 다른 결말 | 테크나 물건 | 맨손으로는 못 가는 결말로 끝난다. 다른 줄기가 그 결말을 읽는다 | 수리 드론 3형이 부서진 드론을 살린다. 이 결말로도 "짓고 있는 것"이 열린다 |

되돌리기가 늘 이득은 아니다. 드론의 선물은 첫 장에서 고쳐 버리면 유물을 못 얻는다. 벽 속의 덩어리를 일찍 떼면 발전원도 없다. "되돌릴 수 있지만 되돌리면 못 보는 것이 있다"가 가지를 고민하게 만든다.

지금 조건으로 쓸 수 있는 "가진 것"은 테크(`테크(이름)`), 테크의 꼬리표(`꼬리표(이름) >= n`), 자원(`자원.부품 >= 2`)이다. 책, 장난감, 유물 같은 **물건**을 조건으로 쓰는 문법은 아직 없다. 물건 목록의 형식이 정해지면 `물건(이름)`으로 더한다.

### 줄기를 끊는 법은 그대로다

[Quests/README.md](Quests/README.md)의 다섯 가지 규칙은 낱장에서도 지킨다. 형식이 어떻게 받쳐 주는지만 적는다.

| 규칙 | 형식에서 |
|---|---|
| 단계 사이에 동면이 낀다 | 결과는 바로 적용되지만 이어지는 사건은 다음에 깰 때부터 나온다. 더 띄우려면 `after` |
| 1단계는 무시할 수 있어야 한다 | 첫 장의 `load`를 0이나 1로 둔다. 방치 결과가 다음 장을 연다 |
| 단계마다 요구가 달라야 한다 | 대응의 `needs`와 `cost`를 장마다 다르게 쓴다. 검사 도구는 아직 이것을 못 잡는다 |
| 일찍 끊을 수 있어야 한다 | 앞 장의 대응에 `needs: ["테크(...)"]`와 `ends`를 함께 둔다 |
| 끝나면 뭔가 남는다 | `ends`인데 결과가 비어 있으면 검사에서 주의가 뜬다. 저절로 잦아드는 방치만 예외다 |

## 7. 조건과 결과 쓰는 법

프로그래밍을 몰라도 쓸 수 있게 한 줄짜리 글로 적는다.

### 조건 (`when`, `needs`)

| 쓰는 법 | 뜻 |
|---|---|
| `따뜻한벽.단계 == 정체` | 값이 이것이다 |
| `따뜻한벽.단계 != 끝` | 값이 이것이 아니다 |
| `함선AI.친밀 >= 4` | 4 이상이다. `>` `<` `<=`도 쓴다 |
| `시간.년 >= 5억` | 큰 수에는 만, 억, 조를 붙일 수 있다 |
| `시간.년 >= 시대.초월` | 다른 상태값과 견준다 |
| `함선AI.생각마침` | 켜져 있다 |
| `!함선AI.생각마침` | 꺼져 있다 |
| `테크(금속프린터)` | 그 테크 카드를 가졌다. `!테크(...)`는 안 가졌다 |
| `꼬리표(기계화) >= 2` | 그 꼬리표가 붙은 테크를 2개 이상 가졌다 |
| `A == 1 또는 B == 2` | 한 줄 안에서 `또는`으로 이으면 하나만 맞아도 된다 |

목록의 줄은 전부 맞아야 한다. 컨셉의 네 조건은 이렇게 적힌다.

| 컨셉의 조건 | 적는 법 |
|---|---|
| 무작위 | `draw: opener`와 `weight`. 조건은 비워도 된다 |
| 시간 | `시간.년 >= 시대.성간` |
| 테크 | `테크(...)`, `꼬리표(...) >= n` |
| 선택 | 전에 한 대응이 바꿔 둔 상태값 |

### 결과 (`effects`)

| 쓰는 법 | 뜻 |
|---|---|
| `따뜻한벽.단계 = 정체` | 값을 넣는다 |
| `나.무드 += 3`, `나.무드 -= 3` | 더하고 뺀다. 범위를 넘으면 끝값에서 멈춘다 |
| `배.전력 -= 따뜻한벽.크기` | 다른 상태값만큼 뺀다 |
| `함선AI.생각마침 = true` | 켠다. `false`로 끈다 |
| `테크얻음(이름)`, `테크잃음(이름)` | 테크 카드를 주거나 뺏는다 |
| `유물얻음(이름)` | 분석할 유물을 준다 |
| `일지(글)` | 일지에 한 줄을 남긴다 |
| `엔딩(이름)` | 엔딩으로 간다 |

명령은 게임을 만들면서 늘린다. 늘릴 때는 검사 도구의 명령 목록에도 더한다.

## 8. 연출자 초안

깰 때마다 무엇을 낼지 고르는 규칙이다. 아직 게임 코드가 없으므로 규칙만 적는다. 숫자는 `directors.json`에 두어서 모드와 시작 세팅으로 바꿀 수 있게 한다.

### 한 번 깰 때의 순서

1. **지난 방치를 정산한다.** 지난번에 드러났는데 대응하지 않은 사건마다 방치 결과를 적용한다. 결과는 일지에 남는다. 맞은 뒤에 이유를 알 수 있게 하기 위해서다.
2. **이어지는 사건을 낸다.** `followup` 가운데 조건과 간격이 맞는 것을 전부 모은다. 한 번에 낼 수 있는 수(`maxFollowupsPerWake`)를 넘으면 부담이 큰 것부터 내고 나머지는 다음으로 미룬다. 이어지는 사건은 약속이므로 뽑기에 맡기지 않는다.
3. **새 사건을 뽑는다.** 아래 예산이 남았으면 `opener` 가운데 조건이 맞는 것을 가중치로 뽑는다. 예산이 찰 때까지, 한 번에 `maxNewPerWake`개까지.
4. **언제 드러낼지 나눈다.** `wake`는 깨자마자 배에 놓여 있다. `awake`는 깨어 있는 며칠 가운데 하루에 생긴다. `sleep`은 다음 동면 중에 생겨서 깨운다.

### 긴장 예산

림월드의 위협 점수와 같은 생각이다. 사건마다 `load`(부담 0~5)가 있고, 지금 열려 있는 사건의 부담을 다 더한 것이 예산을 넘지 않게 한다.

```
예산 = budgetBase + budgetPerLog10Year × log10(흐른 해)   (budgetMax까지)
```

시간에 로그를 쓰는 이유는 이 게임의 시간이 백 년에서 백조 년까지 가기 때문이다. 100년에 2, 100만 년에 6, 100억 년에 10이 더해진다.

예산을 깎는 것:

- 지금 열려 있는 줄기 수가 `maxActiveThreads`를 넘으면 새 사건을 뽑지 않는다.
- 직전에 큰 피해를 입었으면(`배.선체`나 `나.무드`가 크게 떨어짐) `quietWakesAfterDisaster`번은 새 사건 없이 쉰다.

### 가중치를 바꾸는 것

- 사건의 `weightMods`. 예: `{"if": "꼬리표(기계화) >= 2", "mul": 3}`. 가진 테크에 맞는 사건이 더 잘 나온다.
- 지금 열려 있는 줄기와 `targets`가 겹치면 `sameTargetPenalty`를 곱한다. 배만 계속 맞지 않게 한다.
- 부담이 0인 사건(생일, 드론의 선물 같은 것)은 예산을 쓰지 않으므로 숨 돌릴 틈에 낀다.

### 지켜 주는 것

- `guaranteeSignEveryWakes`번 깰 동안 새로 드러난 것이 하나도 없었으면, 예산을 무시하고 부담 0~1짜리를 하나 낸다. "자고 일어났는데 아무 일도 없다"가 이어지지 않게 한다.
- `repeat`가 없는 사건은 한 판에 한 번만 나온다.

### 성격이 다른 연출자

`directors.json`에 두 개를 예시로 두었다. "차분한 항해"는 천천히 오르고 큰일 뒤에 쉰다. "거친 항해"는 쉬지 않고 한꺼번에 몰린다. 시작 세팅에서 고르게 하면 된다.

## 9. 파일과 폴더

### 글 형식 비교

| | JSON | YAML | TOML | Unity 에셋 (ScriptableObject) |
|---|---|---|---|---|
| 손으로 읽고 쓰기 | 괄호와 따옴표가 많다 | 가장 깔끔하다 | 깊이 들어간 목록에 약하다 | 손으로 못 쓴다 |
| 틀리기 쉬운 곳 | 쉼표 하나 빠지면 파일 전체가 안 읽힌다. 대신 바로 안다 | 들여쓰기가 한 칸 틀려도 읽히고 뜻만 달라진다. `no`, `on`, `1e3` 같은 글이 멋대로 다른 것으로 바뀐다 | 적다 | 없다 |
| Unity에서 읽기 | 기본으로 된다 | 외부 라이브러리를 넣어야 한다 | 외부 라이브러리를 넣어야 한다 | 기본이다. 다만 빌드에 구워져서 실행 중에 못 더한다 |
| 웹 도구, 파이썬에서 읽기 | 기본으로 된다 | 라이브러리를 넣어야 한다 | 파이썬만 기본으로 된다 | 못 읽는다 |
| 모드 | 폴더에 넣으면 끝 | 같다 | 같다 | 에디터가 있어야 만든다 |

**JSON을 추천한다.** 이유는 셋이다.

1. 게임, 검사 도구, 지도 도구가 전부 아무것도 더 설치하지 않고 읽는다.
2. 틀리면 조용히 넘어가지 않고 바로 실패한다. YAML의 조용한 실수는 수백 개가 쌓였을 때 찾기 어렵다.
3. **파일을 손으로 쓸 일이 거의 없다.** 지도 도구에서 칸을 채워 저장하면 도구가 파일을 쓴다. 손으로 쓰기 불편하다는 JSON의 약점이 가려진다.

대신 조건과 결과는 JSON 구조로 쪼개지 않고 `"함선AI.친밀 >= 4"` 같은 한 줄 글로 둔다. 구조로 쪼개면 사람이 못 읽는다.

### 폴더 구조

```
SO/Content/
  base/                    기본 묶음
    pack.json              묶음의 이름, 판, 의존하는 묶음, 끌 사건 목록
    threads.json           줄기 목록 (id, 이름, 색)
    states.json            상태값 선언
    techs.json             테크 카드와 꼬리표
    directors.json         연출자 설정
    events/
      생일.json            줄기마다 파일 하나. 안에 사건이 여러 장
      따뜻한벽.json
      ...
  mods/
    <모드 이름>/           같은 구조. pack.json이 있으면 묶음으로 본다
```

- 사건을 어느 파일에 넣는지는 규칙이 아니다. 줄기마다 한 파일이 고치기 편해서 그렇게 했을 뿐이다. 하위 폴더를 만들어도 읽는다.
- 지금은 `SO/Content/`가 Unity의 `Assets` 밖에 있다. 게임 코드가 이 자료를 읽기 시작할 때 `Assets/StreamingAssets/Content/`로 옮기면 된다(빌드에 파일 그대로 들어가는 폴더다). 지금 밖에 둔 이유는 기획 단계에서 Unity 에디터를 건드리지 않기 위해서다.

### 모드가 할 수 있는 것

| 하고 싶은 것 | 방법 |
|---|---|
| 사건, 줄기, 상태값, 테크를 더한다 | 자기 묶음에 파일을 넣는다 |
| 기본 줄기에 사건을 끼운다 | 기본 묶음의 상태값을 조건으로 읽는 사건을 쓴다. 기본 파일은 건드리지 않는다 |
| 기본 사건을 바꾼다 | 같은 `id`의 사건에 `"override": true`를 넣는다 |
| 기본 사건을 끈다 | `pack.json`의 `disable`에 id를 적는다 |
| 연출자를 더한다 | `directors.json`에 더한다 |
| 시작 세팅을 더한다 | 아직 형식이 없다. 상태값의 시작값과 가진 테크를 적는 파일이 될 것이다 |

묶음은 `base` 다음에 `mods/` 아래를 이름순으로 읽는다. 같은 id가 `override` 없이 두 번 나오면 오류다.

## 10. 검사 도구가 잡는 것

`SO/Tools/QuestMap/퀘스트검사.bat`을 누르거나 지도를 열면 돌아간다. **오류**는 게임이 읽을 수 없거나 틀림없이 잘못된 것이고, **주의**는 의도한 것일 수도 있는 것이다. 오류가 없으면 통과다.

지금 잡는 것:

| 등급 | 문제 |

| 오류 | 파일이 JSON으로 안 읽힌다 |
| 오류 | 같은 id가 두 번 나온다 |
| 오류 | 제목, 나오는 법, 언제 드러나나가 없거나 틀린 값이다 |
| 오류 | 줄기가 `threads.json`에 없다 |
| 오류 | **징후가 없다** (보이는 것도 들리는 것도 없음) |
| 오류 | **방치 결과가 없다**, 또는 방치의 `tone`이 없다 |

| 오류 | 선언하지 않은 상태값을 쓴다 (오타) |
| 오류 | 상태값에 없는 값을 넣거나 견준다, 종류가 안 맞는다, 범위를 넘는 수를 넣는다 |

아직 못 잡는 것 (다음에 넣을 것):

- 조건이 맞아도 실제로는 순서상 못 오는 경우 (지금은 "값이 한 번이라도 될 수 있나"만 본다)
- 숫자 관문에 닿을 만큼 올려 주는 곳이 충분한지 (`일손.드론마음 >= 2`인데 올리는 곳이 한 군데뿐인 경우)
- 한 줄기에서 같은 요구를 세 번 연속으로 하는지
- 두 줄기가 같은 곳(`place`)을 동시에 차지하는지
- 한 시대에 사건이 너무 몰려 있거나 비어 있는지
- 실제로 판을 수천 번 돌려 보고 어떤 사건이 한 번도 안 나왔는지 (연출자를 만든 뒤에 가능하다)

## 11. 지도 도구

### 어디에 만들었나

| | Unity 에디터 창 | 자료에서 그리는 웹 화면 |
|---|---|---|
| 여는 법 | Unity를 켜고 메뉴에서 연다 | 파일을 두 번 누르면 브라우저에 뜬다 |
| 모드 만드는 사람 | Unity가 있어야 쓴다 | 그냥 쓴다 |
| 배의 방과 잇기 | 씬의 방을 바로 고를 수 있다 | 방 이름을 글로 적는다 |
| 만들고 고치는 속도 | 코드를 고칠 때마다 Unity가 다시 읽는다. 열려 있는 다른 작업이 끊긴다 | 새로 고침이면 된다 |
| 큰 지도 | 그래프 화면 기능이 바뀌는 중이라 불안하다 | 수백 장도 문제없다 |

**웹 화면으로 만들었다.** 가장 큰 이유는 모드다. 모드를 만드는 사람에게 Unity를 요구할 수 없다. 둘째로 지금 다른 작업이 Unity 에디터를 쓰고 있어서 에디터 코드를 넣으면 그쪽이 끊긴다. Unity 안에서 필요한 것은 "사건의 `place`가 실제 배의 어느 방인가"를 잇는 일인데, 이것은 게임 코드가 생길 때 얇게 붙이면 된다.

치르는 값은 파이썬이 깔려 있어야 한다는 것이다. 나중에 실행 파일 하나로 묶을 수 있다.

### 여는 법

1. `SO/Tools/QuestMap/퀘스트지도열기.bat`을 두 번 누른다.
2. 검은 창이 하나 뜨고 브라우저에 지도가 열린다. 검은 창은 켜 둔다. 닫으면 지도가 꺼진다.

### 보는 법

- **네모** 하나가 사건 한 장이다. 왼쪽 띠의 색이 줄기다. ▶는 연출자가 새로 뽑는 사건이고, ↻는 되풀이하는 사건이다. 오른쪽 아래 점의 색이 방치하면 어떻게 되는지다.
- **가로 띠** 하나가 줄기다. 왼쪽에서 오른쪽으로 진행한다.
- **둥근 알약**은 여러 줄기가 함께 건드리는 상태값이다. 위에 떠 있는 보라색은 올리고 내리는 숫자, 줄 사이의 연두색은 다른 줄기를 여는 `결말` 값이다.
- **실선**은 대응하면 이어지는 길, **점선**은 방치하면 이어지는 길이다. 점선의 색이 방치의 방향이다.
- 사건이나 알약을 누르면 이어진 것만 밝아지고 오른쪽에 내용이 뜬다.
- 왼쪽의 **줄기**를 누르면 그 줄기와 엮인 것만 밝아진다. **문제**를 누르면 검사 도구가 찾은 것이 뜨고, 누르면 그 사건으로 간다. 문제가 있는 사건에는 빨간(오류) 또는 노란(주의) 동그라미가 붙는다.
- 끌어서 이동하고, 휠로 확대한다. 위의 검색 칸에 글을 치면 맞는 사건만 밝아진다.

### 고치는 법

- 사건을 누르고 **고치기**를 누르면 칸이 뜬다. 채우고 **저장**하면 파일에 쓰이고, 검사가 다시 돌고, 지도가 다시 그려진다.
- **＋ 새 사건**으로 새로 만든다. 사건을 누르고 **＋ 뒤에 잇기**를 누르면 같은 줄기의 이어지는 사건으로 시작한다.
- 줄기와 상태값도 왼쪽 탭에서 만들고 고친다.
- 조건과 결과 칸 아래에 쓰는 법이 적혀 있고, 상태값 이름을 골라 넣는 목록이 있다.
- 저장은 파일을 바로 바꾼다. 되돌리려면 git으로 되돌린다.

### 아직 없는 것

- 지도 위에서 선을 끌어 사건을 잇는 기능. 지금은 칸에 상태값을 적어서 잇는다.
- 사건의 자리를 손으로 옮겨 저장하는 기능. 자리는 매번 저절로 잡힌다.
- 확률로 갈리는 결과(`rolls`), 가중치 보정(`weightMods`), 테크 목록을 고치는 칸. 파일에 적으면 보이기는 한다.
- 되돌리기 버튼.
- 모드 묶음을 골라서 그 안에 새로 만들기. 지금은 새 사건이 기본 묶음에 들어간다.

[GameConcept.md](GameConcept.md)는 고치지 않았다. 다음을 옮겨 적으면 좋다.

- 9장 이벤트: "모든 이벤트에는 놓치고 잤을 때의 결과가 있고, 그 결과는 나빠짐, 잦아듦, 좋아짐, 섞임 가운데 하나다."
- 9장 이벤트: "이벤트는 동면이 끝나고 일어나 보니 이미 벌어져 있는 것, 깨어서 지내는 며칠 사이에 생기는 것, 동면 중에 생겨서 나를 깨우는 것으로 나뉜다."
- 7장 시간과 시대: 시대가 흔들리는 방식 (판마다 시작 해를 굴린다).
- 16장 제안의 "일지": 방치 결과를 정산할 때 일지에 남긴다는 것과 맞물린다.
- 17장 4번 시작 세팅: 연출자를 시작 세팅에서 고를 수 있다.

## 14. 정해야 할 것

1. **자료의 말.** 상태값 이름과 사건 id를 한글로 했다(`함선AI.자율성`). 읽기는 좋지만 영어권 모드 제작자에게는 벽이다. 한글로 계속 갈지, 영어 id에 한글 이름을 따로 붙일지.
2. **도구의 자리.** 지도 도구를 Unity 밖 웹 화면으로 만들었다. Unity 안에서 고치고 싶은 마음이 크면 방향을 바꿔야 한다.
3. **이어지는 사건은 반드시 오는가.** 지금 초안은 "조건이 맞으면 반드시 온다"다. 가끔 건너뛰거나 늦게 오게 할 수도 있다.
4. **방치의 기준.** "드러났는데 대응하지 않고 잤다"를 방치로 본다. 플레이어가 아예 못 본 것도 방치로 칠지, 본 것만 칠지.
5. **한 번에 열려 있는 줄기 수.** 초안은 4개다. 깨어 있는 날이 1~7일이라는 점에서 맞는 수인지.
6. **드는 것(`cost`).** 지금은 글이다. 시간과 자원을 실제 숫자로 적게 할지는 깨어 있는 구간의 시간 규칙이 정해져야 한다.
7. **좌표와 만남.** 다음 목적지를 고르는 일과 교역 상대는 이 형식에 아직 없다. 좌표도 사건처럼 낱장으로 쓸 수 있을 것 같지만 따로 설계해야 한다.
8. **동면을 도중에 끊기.** 사건이 나를 깨우는 것(`sleep`)은 형식에 있다. 플레이어가 스스로 동면을 취소할 수 있는지, 강제로 깨워졌을 때 다시 잠드는 데 대가가 있는지는 정하지 않았다. 정해지면 "동면 중에 깨움" 사건의 대응에 "다시 잔다"가 들어간다.
9. **물건을 조건으로 쓰기.** 책, 장난감, 유물 같은 물건이 있으면 열리는 대응. 물건 목록을 어디에 어떻게 적을지가 먼저다.
10. **예시 100개를 어디까지 옮길지.** 마음에 드는 것을 고르면 그 결을 따라 옮기고 늘린다.
